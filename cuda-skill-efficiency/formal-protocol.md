# 封存的首轮正式对照约定（运行前，2026-09-27）

## 问题与任务

在这台消费级 GPU 上，以 OpenCode 1.18.12 和请求模型 `deepseek/deepseek-flash`，比较同一 CUDA/Triton 开发任务的三种附加提示：无、完整、人工精简。正式题目为 `tasks/heldout/softmax_rows` 与 `tasks/heldout/layernorm_rows`。两者在本轮 agent 运行前封存；开发任务 `vector_affine`、`row_reduce` 不进入正式结果。任务及规则的 SHA-256 随每次 `run.json` 保存，评测公共代码的 SHA-256 随 `evaluation.json` 保存。

## 运行顺序与上限

每题每条件重复三次，共 18 次。每次从原始候选独立复制到随机临时任务目录，使用同一 Python 环境、工具权限、模型标识、提示模板和 300 秒墙钟上限。顺序预定为：

| 重复 | `softmax_rows` 顺序 | `layernorm_rows` 顺序 |
| --- | --- | --- |
| 1 | 无、完整、精简 | 完整、精简、无 |
| 2 | 完整、精简、无 | 精简、无、完整 |
| 3 | 精简、无、完整 | 无、完整、精简 |

按表逐行执行，每行先 softmax 后 layer norm；不并发运行 GPU 评测。因载体无法强制 token 上限，本轮只报告观察到的质量与总消耗，不声称固定 token 预算。请求的模型标识固定，但供应端精确修订号未暴露。

## 预定结果口径

正确性要求全部三个形状数值通过，且每个形状确实启动 Triton kernel；失败、超时和缺失用量各自保留，不能挑选成功轨迹。正确候选使用 20 对随机交错的 CUDA 图计时，每次图内重复 32 次。报告每条件的完成数、正确数、有效提速数（提速比大于 1）、速度比原始样本和分布；成本分别列出附加提示估算 token、实际未缓存输入、缓存输入、可见输出和推理输出，以及总 token。重点观察任务质量随总消耗的变化，不用成功率除以 token 的单一比值替代。

单任务或少量重复不支持跨任务泛化。只有若完整提示出现稳定的规则利用不足、明确约束违反，或相对精简提示有明显额外成本却无质量收益，才考虑人工挑选清楚的规则做执行责任迁移；本轮不自动进入机制实验。
