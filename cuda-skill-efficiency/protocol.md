# AI4CUDA skill 效率实验约定（初版）

## 研究对象

第一阶段研究 CUDA kernel 开发 agent，而不是一般编程 agent。每个任务提供相同的参考计算、输入规格和候选接口；正确性检查与计时在 agent 工作目录外运行。单个 CUDA 工作流的结果只支持该工作流的结论。不同任务制式的规则不交叉使用。

## 配对与记录

同一模型版本、工具权限、任务副本和执行上限下，交错运行三种条件：无额外 skill、完整 skill、人工精简 skill。精简版必须保留完整版的可操作约束和领域提示，并在正式运行前由人工逐项核对；无额外 skill 仍收到完成任务必需的接口说明。开发任务可用于修订任务与材料，正式任务在运行前封存，同一题的所有重复运行只在一边。

每次运行保存：任务与 skill 文件的哈希、模型标识及可取得的精确修订号、agent 工具事件与反馈、每轮原始 token 用量、结束原因、候选源码与哈希、独立正确性结果、原始计时、GPU 与软件环境。缺失事件或 token 用量的运行标为 `incomplete_trace`，不用于效率比较。记录载体实际暴露的用量粒度；若仅给整个 agent 任务回合的合计，不能声称取得内部每次模型请求的用量。prompt 中的 skill token 数与实际运行输入/输出 token 分开报告；缓存 token 单列，不把工具调用次数或墙钟时间伪装成 token。

任务质量以独立正确性为先决条件。错误候选无性能分数；正确候选报告与固定参考实现的延迟比和原始样本。微秒级差异需多轮乱序重测，波动大时标为不确定。性能或正确性评测失败必须保留原始记录及原因。

第一阶段的最低用量粒度是每次完整任务运行的输入、输出和缓存 token 合计；内部逐次模型请求的用量只支持进一步分析过程，不是任务级效率对照的前置条件。若运行载体无法强制 token 上限，结果只能是观察到的质量与成本关系，不能声称固定 token 预算实验。所有条件的额外测试、重试与工具调用上限一致。

## 采集可行性门槛

优先复用可输出事件流的现成 agent，仅编写隔离任务、切换 skill 和保存事件的薄封装。先以两项 CUDA 任务完成三条件配对试跑；逐项核查模型和规则版本、至少每轮用量、工具调用和反馈、源码、正确性、计时及终止原因。薄封装若无法取得这些证据，核查现有可观测 CUDA agent 载体；仍不可行则记录失败并停止效果推断。试跑不充当正式效果样本。

## 进入后续阶段的条件

正式数据若显示完整 skill 的内容未被稳定使用、明确约束被违反，或相对精简版成本明显上升而任务质量未改善，才人工选少量原意清楚的规则做执行责任迁移。对照包括完整、精简、完整加相同机制、精简加相同机制；同时检查违规和误拒绝合法 CUDA 实现。机制所做的额外检查及计算要显式计入。若现象仅由文字缩短或计算增加解释，不归功于机制化。未见瓶颈则以负结果结束，不开发通用规则引擎。
