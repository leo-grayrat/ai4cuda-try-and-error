# AI4CUDA skill 效率首轮正式结果（2026-09-27）

## 实验范围

按 [运行前封存的约定](../formal-protocol.md)，OpenCode 1.18.12 请求 `deepseek/deepseek-flash`，在同一台 RTX 5060 Laptop GPU 上，对两个未用于开发试跑的 Triton 任务各运行三种附加提示、每种三次，共 18 次。任务是适配本机输入规模的逐行 softmax 和无仿射参数 layer norm；不是官方 KernelBench 分数。无额外 skill 条件仍包含任务接口和“必须使用 Triton”的要求。

完整提示约 399、精简提示约 168 个 `o200k_base` 估算 token；它们并非 DeepSeek 的精确计数。运行成本来自 OpenCode 每步事件，缓存输入与未缓存输入分列保留在 [机器可读汇总](formal-summary.json) 中。没有可强制的 token 上限，因此结果是观察到的质量与成本，不是固定 token 预算曲线。

## 质量与成本

“有效”要求 agent 正常结束、三个形状数值正确且每个形状实际启动 Triton kernel。“提速”要求有效并且 GPU 图配对计时的参考/候选延迟比大于 1。中位 token 包含每组全部三次尝试，包括失败或超时；提速比按重复顺序列出，`×` 表示该次未达到有效条件。

| 任务 | 附加提示 | 有效/3 | 提速/3 | 总 token 中位数 | 各次提速比 |
| --- | --- | ---: | ---: | ---: | --- |
| softmax | 无 | 3 | 3 | 178,792 | 1.526、1.184、1.446 |
| softmax | 完整 | 2 | 2 | 184,682 | 1.523、×（超时）、1.212 |
| softmax | 精简 | 3 | 2 | 170,116 | 0.838、1.023、1.023 |
| layer norm | 无 | 3 | 3 | 125,135 | 1.196、1.401、1.448 |
| layer norm | 完整 | 2 | 2 | 380,774 | ×（复制参考实现）、1.638、1.022 |
| layer norm | 精简 | 3 | 3 | 211,833 | 1.025、1.024、1.230 |

跨两题合计，无额外提示为 6/6 有效、6/6 提速，完整提示为 4/6 有效、4/6 提速，精简提示为 6/6 有效、5/6 提速。这是 2 题 × 每格 3 次的描述性结果，不能解释为真实成功率或统计显著差异。完整提示在某些运行生成了较快的候选，例如 layer norm 的 1.638 倍，因此也不能概括成“完整版没有质量收益”。

完整提示相对精简提示的总 token 中位数在 softmax 高 8.6%，在 layer norm 高 79.8%。主要差异来自后续执行路径，而非文档长度本身：layer norm 完整提示的第二次运行用了 26 个模型步骤、26 次工具调用和 801,907 个总 token，进行了大量测试与调参；同条件第一次运行只用了 3 步、49,288 token，最后直接复制了 PyTorch 参考实现。两者都属于实测行为，不能从这三次推断是哪条规则造成它们。

softmax 完整提示的第二次运行在 300 秒上限超时；事件流最后一条出现在约第 44 秒，之后没有新事件。残留候选虽通过数值与 Triton 检查，仍按预定规则记为超时。现有事件无法确定这段等待发生在供应端、CLI 还是未返回的内部步骤，也不能归因于 skill。

## 计时与数据审计

正确候选使用 20 对随机交错的 CUDA 图计时，每次图 replay 含 32 次重复。六条接近 1 倍或低于 1 倍的运行另存 `evaluation-repeat.json` 复测：softmax 精简三次原始/复测分别为 0.838/0.836、1.023/1.022、1.023/1.024；layer norm 精简前两次为 1.025/1.021、1.024/1.015，完整提示第三次为 1.022/1.011。约 1%–2% 的优势很小，虽复测方向未翻转，仍应视为性能边界案例，不把阈值计数解释为稳定提速幅度。

18 条运行的任务、规则、参考和评测哈希分别一致；OpenCode 版本与请求模型标识一致；无缺失的逐步用量或工具反馈。检查工具输入没有发现本轮试验读取其他 trial 或仓库结果的路径。隔离采用系统临时目录的独立随机任务目录，降低意外串扰，但并非操作系统级文件沙箱。供应端精确模型修订号不可取得。原始 `events.jsonl`、提示、源码快照、评测样本和 stderr 已入库于 [`traces/`](traces/README.md)，不包含 Triton 编译缓存；[汇总脚本](../summarize_formal.py)会校验哈希与事件计数并重建 [JSON 汇总](formal-summary.json)。

## 第一阶段判断

这批任务没有显示附加的通用 skill 在质量与总消耗之间带来稳定优势；无额外提示在两题中表现最好，但任务契约已提供关键操作要求。完整提示出现一次明确约束违反和一次超时，同时也出现较快候选与高计算成本；目前不能把这些差异归因于文档长度或某条规则。

因此**暂不进入执行责任迁移实验**。现有独立检查器能识别“复制参考实现”的失败，但若给 agent 增加检查反馈和重试，就会增加计算；仅凭当前一次违规无法判断机制是否优于保留、精简或删除提示。要研究迁移，需要先在更多匹配的 AI4CUDA 任务及较长的真实规则材料上复现明确、可解释的瓶颈，并给所有对照相同的重试和工具预算。本轮结论只限于这里的两项改编 Triton 任务和这版模型、工具、硬件。
