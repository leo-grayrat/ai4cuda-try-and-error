## 载体判断与下一步门槛

当前封装只负责隔离任务、提供提示、记录 CLI JSON 事件与源码版本、调用独立评测；agent 决策循环仍由 CLI 执行。它已能记录第一阶段所需的任务级输入、输出和缓存 token 合计，以及可见工具事件。精确模型修订号、内部逐次请求用量和内置上下文开销不可分辨，限制更细的过程解释，但本身不是任务级效率对照的阻断条件。此次不可比较的直接原因是三个条件未跑齐、两次试跑环境不一致，以及完整提示运行超时。其他现成 CLI 也未给出可用的替代轨迹：OpenCode 起初因默认配置目录不可写而无法启动；改用项目内独立配置、数据和缓存目录后能启动并输出 JSON 事件，但最小模型请求向当前 `ANTHROPIC_BASE_URL` 配置的接口发送后收到 HTTP 405。Claude 的最小请求连续 API 重试。这里没有把接口故障误报成 CUDA agent 的效果或仓库权限问题。

因此暂停扩大运行。下一步可继续使用现有 Codex CLI，但须先以一项有区分度的 CUDA 开发任务核查三个提示条件是否能在同一 Python/GPU 环境、权限和执行上限下完成，并稳定保存源码、工具反馈、终止原因及任务级 token 合计；随后才用第二项任务复核采集链路。实际提供给模型的服务器端版本未暴露时，固定请求的模型标识、CLI 版本和运行时段，并把版本不可核实列为限制。只有配对试跑通过才封存正式任务、重复比较质量与总成本；此处没有 skill 效果的正负结论，也没有执行责任迁移结论。
