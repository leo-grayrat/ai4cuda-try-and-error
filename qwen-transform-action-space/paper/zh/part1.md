# Token 级是错误的坐标系吗？——把程序变换作为 LLM 驱动内核优化的动作空间

**立场与分析论文（Position and analysis paper）。** 草稿：第 4 阶段（v2，经五位审稿人模拟同行评审后修订；修订日志见 `stage4_revision/REVISION_NOTES.md`）。第 3 节所有分析数字均由公开数据计算得出，并可由随附脚本复现；第 3.6 节报告了该次评审在 v1 中发现的一处统计错误。

## 摘要

生成 GPU 内核的强化学习（reinforcement-learning）系统在采样文本上更新策略（policy），然后在长达数千个决策的轨迹（trajectory）末端挂上唯一一个执行层奖励。然而性能是少数几个*程序设计决策*的属性——融合（fuse）两个 pass、不再把某个中间结果实体化（materialize）、改变每线程工作量——而每一个决策都横跨众多 token 和若干空间上分离的代码位置才得以实现。我们追问：这究竟不只是一个信用分配（credit assignment）上的麻烦，而是在*坐标系（coordinate system）*之选择本身上的一个错误，即动作单元本身。我们把一个候选动作形式化为带类型的程序变换（program transformation）`a = (τ, ℓ, θ)`，并陈述：要让它成为一个优于整程序生成的接口，有什么必须为真。两个论断必须被分开，而文献并没有把它们分开：K-Search 已经把算法规划与程序实例化解耦，并报告了巨大的增益 [29]；CuAsmRL 已经在显式的调度变换空间上训练强化智能体 [30]；然而，那个描述性前提尚未在公开轨迹上被度量过。因此我们在 AdaExplore 的优化树上对这一前提做经验检验（可用的父→子成功边 2,510 条；跨 45 个任务标注 55 条）。一个冻结的 12 类词表用 10 个类别覆盖了 90.9% 的边，标签熵（2.67 比特）远低于对同一批 diff 的一个忠实描述（4.26 比特的粗粒度结构、5.78 比特的 diff 身份）。有信息量的检验并不是压缩——任何粗粒度摘要都天然享受压缩：在对称置换校准（permutation calibration）下，语义标签对于实测加速比是显著有信息的（plug-in 互信息 0.697 比特，偏差校正后为 0.624，p = 0.0005），而无论是粗粒度 diff 结构（p = 0.752）还是仅 hunk 数（p = 0.436）都没有胜过其自身的零分布。我们报告：这一结果取代了我们初稿中一个方向相反的结论，后者由一项欠校正的 Miller–Madow 项造成，而我们自己那套 69 条断言的对账工具都未能检测到它。相较之下，在我们这一抽样设计下，跨任务复现处于机会水平，并不支持可迁移性论断。因此，本工作的贡献是对某一前提的一次经过校准的度量、一组我们被迫采用的方法论禁令，以及对仍未可判定者的一份证伪协议（falsification protocol）——其中包括"选择很容易而实现才是瓶颈"这一可能性，我们自己的数据反而提示它仍然成立。

## 1. 引言

### 1.1 驱动这一问题的那个经验事实

如今的智能体式强化学习系统已经能写出击败编译器自动调优的 GPU 内核。CUDA Agent 在 KernelBench 的三个难度划分上报告了 100%、100% 和 92% 的快于 `torch.compile` 比率，在最难的划分上比最强的专有模型高出约 40% [1,2]。它达到这一步的方式，是把一个语言模型放进一个真实的开发沙箱——编译、验证正确性、剖析、迭代——并用 PPO 在很长的多轮智能体轨迹上优化策略，上下文长度量级为 10⁵ token [1]。公开的产物是一个 6,000 样本的操作数据集、一份技能规约，以及奖励与预热（warm-up）的训练配方；模型权重、智能体轨迹和训练期可观测量并不公开 [1,3]。

仅从摘要和公开配方的层面来读，训练那一侧的机制是一连串由一般动机驱动的修补：在要求模型跑长 episode 之前，先用更短的 episode 给它预热；在强化学习之前，先在成功轨迹上做监督微调（supervised fine-tuning）；离线预训练一个 critic；给奖励设界，使基于结果的打分不过度奖励那些余量大的任务；约束策略更新幅度以保持稳定。每一步都是对训练底座某一症状的合理回应。而在*我们所能核实的那份材料所描述的范围内*，没有一步是被存储层次（memory hierarchies）、warp 语义、合并访存（coalescing）或共享内存 bank 冲突所逼出来的。

对这一批评需要两点限定，我们赶在一个对手提出之前先把它们写出来。

* **我们无法核实那个系统的动作空间（action space）到底是什么。** 它的摘要描述的是一个带有自动验证与剖析的技能增强型开发环境 [1]。一个嵌在这样环境里、通过文件编辑工具操作的智能体，可能已经在环境层被强加了一种事实上的动作结构。因此我们并不声称 CUDA Agent "把每一个 token 都当作一个独立动作"；我们声称的是：*它所记录的那个学习接口*，是针对一个 episode 级结果做优化的 token 级策略，而任何存在的结构都是工具可供性（tool affordance）的副产物，而非一个被设计出来的动作空间。更强版本的批评需要论文的环境规约，而它不在摘要里。
* **可迁移性论断不可被过度解读。** NKI-Agent 把 CUDA-Agent 框架迁移到 AWS Trainium，并报告带二值编译奖励的 GRPO *未能超过监督微调* [18]。那是强化学习这一组件的一次失败迁移，而不是配方的成功迁移；把它当作"配方原封不动地搬走了"的证据来引用会自相矛盾。它所确实支持的，是一个更窄、对该领域仍然难堪的结论：训练配方欠规定到这种程度——在新硬件上复现它会改变哪些部分存活下来，而强化学习那一部分并不是可携带的核心。

我们坦率地指出，围绕这些设计选择常被复述的那些具体数字细节——精确的奖励层级集合、精确的非对称裁剪边界、CUDA 在预训练语料中的出现频率——在本论文中无法核实。该预印本没有 HTML 渲染，我们也没有解析 17 MB 的 PDF 源打包；内部实现并未公开。因此我们只在摘要所能支持的层面上立论，并对无法核实的部分作标记而非断言。这本身就是第 3.1 节那个数据可得性约束的一个小例证，也是我们的批评被表述为一个关于建模坐标、而非关于该系统设计决策的问题的原因之一。

所以，诚实的问题不是这个结果是否惊人——它确实惊人——而是那个*增量性的科学论断*是什么，以及这些建模选择究竟是取决于这一领域，还是仅仅取决于训练底座。

### 1.2 中间的那个黑洞

这些系统的学习方式与它们被要求产出的东西之间，存在一道结构性缺口。性能是一种*被执行出来的、结构性的*属性。一次从 1.0× 到 1.8× 的跃升，可能可归于一个设计决策——融合两个 pass，消除一次全局内存往返——而其余两千个 token 只是那本来就会被几乎一样地写出来的样板代码。然而训练接口是一个逐 token 的策略更新。流水线里没有任何东西会告诉学习器"第 1,537 步的那个决策才是真正见效的那一个"。价值函数与 GAE 是在 token 序列上*统计地*估计信用。

这一缺口在文献里并非无人察觉；它如今已自成一个研究领域。一篇近期的综述整合了一个 69 篇论文的语料库，收录面向 LLM 强化学习的信用分配（credit-assignment）方法，并恰恰按*粒度（granularity）*来组织——轨迹、段、步、token——且报告稀疏的结果奖励"说得很少：究竟是哪个 token、哪个推理步骤、哪次工具调用、哪个内存操作、或哪个智能体造成了某个结果"[35]。因此，当前的实践已经在轨迹之下施加干预：过程奖励、段级优势重加权、轮次级可验证监督、反事实 token 信用。我们的论断并不是信用无人处理，而是一个不同的论断：几乎所有那些工作改变的都是**信用目标**，而把**动作单元**留在 token 上，于是学习器仍把单个程序决策当作数百个独立动作，而它必须以统计方式去发现它们的联合实现。对 token 重新加权与给动作重新赋型是两种正交的补救，而第二种才是那个会消除对第一种之需要的补救。

标准的回应是更好的信用分配（credit assignment）：找出重要的片段、对它们重新加权、把 critic 练得更锐。我们此前的工作正是用基于正则的源码定位器和带 oracle 标注的片段尝试了这一点，并以一种有教益的方式失败了。单个优化决策可以散布在内核主体、一处索引计算、一个共享内存声明和主机端的启动参数之上；反过来，同一个决策可以由完全不同的代码来实现。定位器之所以不断漏掉东西，是因为它们想从*文本局部性*中恢复出一个*程序决策单元*，而这两者之间并非一一对应。

正是那次失败，把问题往上推了一层。

### 1.3 重构问题

训练系统凭什么一开始要把四十个 token 当作四十个动作？它们是同一个程序决策的同一个实现。于是问题不再是"奖励应该落在哪些 token 上"，而变成：

> **token 级动作空间本身，对于 LLM 驱动的内核优化而言，是不是一个错误的坐标系？**

具体而言：CUDA 优化是否容许一个比 token 更稳定、更可迁移的自然动作空间？把搜索与学习接口搬到它上面，会不会可度量地改变搜索效率与学习效率？

我们把候选动作写作

```
a = (τ, ℓ, θ)
```

即变换的*类型*、*位置*、*参数*。承重的结构是一种多对多关系：

```
one semantic action   →  many tokens, many code sites
very different code   →  the same semantic action
```

设想把每线程工作量从一个元素增加到两个。在 CUDA C++ 里，这需要在内核主体中引入一个新的索引表达式（`int j = i + stride; if (j < n) ...`），*同时*需要主机端把块数从 `N/T` 改为 `N/(2T)`。这两处编辑在文件里相隔很远，任何单独一处都不构成那个动作。这就是我们所指的那个对象的形状。

### 1.4 什么才算数，以及本文实际主张什么

这个想法有一个没有研究价值的平凡版本："编译器 pass 比 token 更具语义"是编译方向的人几十年来早已知道的事实，而 Halide、TVM、Ansor 早已把调度变换放在它们搜索空间的中心 [8,9,10]。若我们的结论仅此而已，那我们不过是重新发现了 IR。

那个非平凡的论断是专门针对 LLM-in-the-loop 优化的：

> 把接口从*生成整个程序*搬到*选择一个参数化程序变换（parameterized program transformation）、再把它实现出来*，会可度量地改变搜索效率与学习效率。

而它有一个前提，必须在这一切值得动手构建之前被检验：

> **真实的、成功的内核优化轨迹，能否由一小套反复出现的程序变换来解释？**

如果每一个成功的子节点都是一次性的、无法归入某个稳定词表的重写，那么这个方向就是死的，再多基础设施也救不回来。相反，如果边不断落在反复出现的模式上——增加每线程工作量、消除一个中间结果、合并内核、重新分块共享内存、改变归约结构——而同一个模式以截然不同的代码出现，那么我们就得到了那个值得研究的现象：**高 diff 熵、更低的变换熵**。那将是迫使我们去承认一个比 token 更自然的结构的数据，而不是我们凭空发明一个抽象来发论文。

本文做三件事：

1. **精确陈述论题，并把常被混为一谈的几类论断分开**（第 2 节）：即把"变换是稳定的描述单元"这一*描述性*论断、"它们改变搜索效率"这一*搜索*论断、以及"它们改变学习效率"这一*学习*论断分开。第一个对后两个是必要的，但绝不充分。它还把"变换"这一切分与相邻的*轮次级（turn-level）*和*编辑级（edit-level）*切分分开，后两者在文献里都已存在 [30,32]。
2. **报告一项在公开轨迹上做的、经过校准的度量研究**（第 3 节）。描述性论断能挺过一次对称置换检验（permutation test）；可迁移性论断则挺不过它自己的零分布。
3. **规约一个可证伪的实验框架**（第 4 节）：五个条件，其中包含一个枚举加成本模型的分支，以及一棵判读树，按其下每一种可能的结果模式都蕴含一个具体的、预先承诺的结论——包括那些直接杀死该方向的模式。由于该协议作为一个*系统*并不新颖——K-Search 已以阳性结果实现了它的 structured-action 条件 [29]——它的价值在于作为一件用来*独立证伪*那类结果的工具，而不在于作为一份争第一的提案。

## 2. 立场：错误的坐标系

### 2.1 训练接口可被切分的三个层次

任何在程序上进行的优化循环都必须决定什么算作一个动作。有三种切分是自然的。

| 切分 | 动作单元 | 信用落在何处 | 失效模式 |
|-----|-------------|-----------------|--------------|
| token | 单个被采样的 token | 在约 10³–10⁴ 步上由 GAE/价值函数估计 | 决策单元不可见；信用是统计性猜测 |
| 编辑区间 / 代码块 | 一段连续的 diff 区域 | 该区间 | 决策并*不*连续；区间会重叠并随意切分 |
| 轮次 / 工具调用 | 多轮循环中智能体的一步 | 该轮次 | 更粗，但一轮仍捆绑了多个独立决策（参见多轮内核 RL [32]） |
| 程序变换 | 带类型的 `(τ, ℓ, θ)` | 所选的那个变换 | 粒度是一种设计选择；实现可能才是真正的瓶颈 |

轮次那一行不是摆设。近期的多轮内核 RL 工作在轮次层面归属奖励，并报告这一点是重要的 [32]，这意味着该领域已经部分地从 token 往上走——只是没有走到一个带类型的程序变换空间上。我们的论断专门关于第四行，而第 4 节必须被读作一个能够把它与第三行区分开来的实验。

中间那一行值得强调，因为大多数"语义"代码 RL 工作实际就坐落在这一行，而且人们很容易假设它已经就是变换那一层。它不是。编辑区间由 diff 算法定义；变换由程序意图定义。当上下文行恰好重复时 diff hunk 会合并，当单个意图跨越一条空行时它会拆分。以它们为基础构建动作，就是以一个文本比较例程的副产物为基础。

### 2.2 形式形状

设 `P` 为一个程序、`ΔP` 为一处改变，且

```
φ : ΔP → a
```

一个从被实现出来的 diff 到动作对象的映射。研究问题是：是否存在一个*简单的* `φ`，其值域很小、跨任务稳定、且忠实于真正引起性能变化的东西。

一个动作由一组分散的编辑来实现，而不是由一个位置：

```
a → { e₁, e₂, e₃, ... }
```

仅此一个观察，就事后解释了第 1.2 节那个定位器失败：寻找"那段优化代码"，是在寻找一个承载非连续决策的连续区域。

### 2.3 粒度：难的那个理论问题

动作空间只有在两个失效极点之间才有用。

* **太粗**——`memory optimization`、`improve ILP`。每个 CUDA 内核都受影响；什么都没被约束；不随之产生任何实现义务。
* **太细**——`change line 172 from i to i+stride`。这是一个 diff；熵坍缩回文本上。

一个好动作比一次 token 编辑更抽象，却又足够具体以*约束实现*。`work_per_thread : 1 → 2` 符合条件：语义确定、硬件后果直接、跨内核反复出现、要求在若干处协调改动，而且比"改善 ILP"具体得多。

因此我们预期最终的产物是一小张带类型的 DSL，而不是一列名词：

```
IncreaseWorkPerThread(axis, k)    Tile(axis, size, mapping)      Fuse(producer, consumer)
EliminateMaterialization(site)    Vectorize(axis, width)         WarpReduce(scope)
```

但本文有意**不**去构建那个 DSL。在现象之存在被确立之前就去设计四十七种动作类型、一套 schema、一个验证器和一个解析器，是最可能产出一大堆答不了任何问题的工程的做法。前提在前。

### 2.4 为什么这不只是"先做计划"

一句"先描述你的计划，再写内核"的提示，并不为任何有趣之事提供证据。它增加了推理 token，或许会有帮助，但那出于完全泛化的理由。我们需要的区分是结构性的：

```
plan-first:      P → free-text reasoning → P'
transformation:  P_t --a_t--> P_{t+1},   a_t ∈ A, reusable, comparable, statable, recurring across tasks
```

自由文本推理没有可学习的结构。一个带类型的动作集有：它支持 `Q(P, a)`，而不是 `Q(P, one particular token string)`。因此任何实验性论断都必须包含一个 free-plan 对照，否则它什么也证明不了。第 4 节把那个对照内置进去。

### 2.5 这里"可迁移"应当意味着什么

有意思的迁移**不是**跨厂商可移植性（NVIDIA → AMD），也**不是**跨架构泛化。一个为某厂商内存系统写的优化，并不会因在另一厂商上失败而被证伪；要求跨厂商的普适性，是把一个硬件论断和一个建模论断混为一谈。

我们在意的迁移是在同一目标平台*之内*、跨内核之间：

```
code_A ≠ code_B   but   a_A = a_B = WarpReduce
```

这样一来，在归约 A 上收集的经验可按动作而非按表层代码来索引，并在归约 B 上复用，从而把 `Q(P, token string)` 变成 `Q(P, a)`。

这就是论题所需要的那个"可迁移"的版本，而且必须立刻标记出来：本文为它最初引用的证据已被撤回。第 3.5 节表明，在一个标签置换零分布下，变换标签的跨任务复现处于机会水平，因为我们的抽样对每个任务的边数设有上限。因此，论题的可迁移性解读**并不为我们的数据所支持**——它是一个需要第 4 节去挣得的假设，而 `Q(P, a)` 在此是被作为一个未来实验的对象来陈述，而不是作为一个发现。

## 3. 初步证据：成功的优化能被压缩吗？

### 3.1 数据，以及为什么是这个语料库

我们使用 AdaExplore 公开的父→子优化轨迹 [3]，它是在 KernelBench [2] 上收集的。这个选择是出于被迫而非出于方便。驱动这一批评的那个系统 CUDA Agent，并不公开智能体轨迹、生成版本、工具调用、反馈日志、逐 token 的 critic 值、原始概率或优势值；公开 issue 追踪器上对此的请求至今无人回应。任何需要那个系统*训练期可观测量*的研究，对外部的人来说根本不可执行 [1]。AdaExplore 是一个公开的搜索轨迹语料库，正是那个前提问题实际所需要的。

每个任务的归档结构：`step_N.py`（即 `ModelNew` 源码）、`step_N_log.json`（MCTS 节点元数据）、`step_N_prompt.txt`、`step_N_metrics.json`（正确性与计时）。

**语料库审计（在任何标注之前）。** 横跨 150 个任务目录共 23,731 个源文件：22,007 个含 Triton 内核，**0 个含 CUDA C++**，1,724 个两者都不含（PyTorch 基线）。这是关于证据基础的一条实质事实，我们直白地陈述它：可用的公开轨迹是 *Triton* 轨迹。Triton 把 `threadIdx`、共享内存和 warp shuffle 藏在一个块级 API 之后，所以我们十二个类别中的两个（`WarpReduce`、`SharedMemoryTransform`）没有可直接观察的实现，而它们恰恰就是那两个从不作为主标签出现的类别（第 3.5 节）。因此我们能检验的论断是关于*调度级*变换的，而不是关于线程级 CUDA 变换的。

### 3.2 边的定义

一条边是一个真正的 MCTS 父→子对，取自显式的 `parent_node_id` 字段——*不是*取自相邻的步号，后者会把树上的子节点与无亲缘关系的兄弟节点混在一起。入选条件：两端都编译且正确，且子节点快出 5% 以上（以 `runtime_stats.mean` 计）。语料库含 **2,510** 条合格边（Level 2 上 1,906 条，Level 3 上 604 条），横跨 145 棵任务树。

我们标注 **55** 条边，横跨 45 个任务（49 条 Level 2、6 条 Level 3），每个任务至多三条，朝最大的改进选取。抽样有意向多 hunk 边富集（55 条中占 33 条），因为"一个动作、若干处位置"正是检验的对象，而均匀抽样会让它难以被观察到。

**这是一个有偏抽样，且这个偏差有两个我们在初稿中未曾意识到的后果。** 它无法估计总体的标签分布，所以第 3.4 节的那些红线是关于这 55 条边的描述性陈述，而非对整个研究纲领的证伪检验。更糟的是，每任务三条边的上限使可达到的不同任务数上限饱和：用 55 条边分布在 45 个任务上，基本上*任何*把标签赋给边的方式都会跨任务铺开。因此我们**撤回**了一个跨任务复现的论断（第 3.5 节），而不是把它淡化。

### 3.3 冻结的词表，以及一处有记录的偏离

十二个类别，在阅读任何一条边的 diff *之前*就被冻结，而且这次冻结只依赖语料库级的元数据（目录结构、JSON 字段、上面那份语言普查）——从不依赖边的内容，那才是会构成泄漏的东西。类别名及其数量与设计草图保持一致；只把它们的*定义*从 CUDA 线程级的措辞改写为调度级语义，并给出两种备选实现（CUDA C++ / Triton），因为第 4.1 节表明数据不含 CUDA C++。

这十二个是：`Fuse`、`EliminateMaterialization`、`Tile`、`IncreaseWorkPerThread`、`Vectorize`、`ChangeLaunchConfig`、`WarpReduce`、`SharedMemoryTransform`、`PrecisionChange`、`LoopTransform`、`HostDeviceOverlap`、`Other`。

标注为多标签、其中指定一个主标签，在可恢复时带一个参数域 `θ`，附一份动作所落到的代码区域列表，以及一段必须引用具体被改动行的自由文本理由。`Other` 要求对"为什么十一个具体类别中每一个都被否决"给出明确交代。

**标注由机器生成。** 设计草图要求由人来阅读三十到五十条边。这一次执行用一个自动化标注器取而代之，第 7 节陈述了由此产生的循环性风险：词表与标注器出自同一个认知家族，所以标注流程对它所检验的假设并不独立。

### 3.4 事先规约的红线

两个预先承诺的诊断阈值，无论它们令人舒服与否都予以报告：

| 条件 | 阈值 | 观测值 | 是否触发 |
|-----------|-----------|----------|--------|
| 任一类别占比 > 40% 的边 ⇒ 词表过粗 | 40% | `Fuse` 30.9% (17/55) | **否** |
| `Other` > 25% ⇒ 该猜想可能为假 | 25% | 9.1% (5/55) | **否** |

两个阈值在*数值上*都没有触发。因两个缘故，二者都比看上去更弱。

* 这些阈值本被设计为总体级的证伪判据，但此刻是在第 3.2 节那个多 hunk 富集、每任务设上限的样本上评估，而该样本无法估计总体分布。把"未触发"读作"词表既不太粗也不是虚构"是一种过度声称，我们把它撤回。
* `Other` 比率低估了概念上的失败。五条 `Other` 边结果都是*同一个*缺失动作（第 3.7a 节）：一个需要新增一个类别来吸收其 100% 拒绝的词表有一个结构性缺口，即便 9.1% 的边远低于 25%。那条数值红线被一个与之相矛盾的定性证据所驳倒的统计量给放了过去。两者我们都报告。

### 3.5 结果：描述性前提存活，但它最初的两项支持统计量作废

前提问题得到一个有条件的"是"。

| 量 | 取值 | 状态 |
|---|---|---|
| 词表复用率 \(\|V\|/\|E\|\) | 10 / 55 = 0.18 | 有意义 |
| 不需要 `Other` 的边占比 | 90.9% | 有意义，但见 3.4 |
| \(H(\text{primary label})\) | 2.67 比特；占其自身最大值（10 个单元格）的 0.805 | 有意义 |
| \(H(\text{coarse structure descriptor, 24 cells})\) | 4.26 比特；占最大值的 0.928 | 有意义的对照 |
| \(H(\text{diff fingerprint})\) | 5.78 比特，恰好等于 \(\log_2 55\) | **恒等式，而非证据** |
| 在两处或更多分离区域被标注的边 | 30 / 55 = 54.5% | **无法归于单个动作** |

主标签计数：`Fuse` 17、`PrecisionChange` 15、`HostDeviceOverlap` 7、`Other` 5、`ChangeLaunchConfig` 3、`Vectorize` 3、`EliminateMaterialization` 2、`Tile` 1、`LoopTransform` 1、`IncreaseWorkPerThread` 1。若把次标签也计入，`WarpReduce` 与 `Vectorize` 各达到 6 次出现；`SharedMemoryTransform` 一次都没有出现。

**我们撤回了什么。** 初稿从逐类别多样性表中作出了两个如今作废的论断：

1. *"没有任何类别曾两次产生同一个 diff。"* 全部 55 个 diff 指纹都互不相同，所以 `distinct_diffs(label) == occurrences(label)` 对**任何**标注都成立，包括一个随机标注。这一列无法在各假设之间作出判别；对这一恒等式的一份审计被输出在 `data/informativeness_calibration.json`（`identity_audit`）。相应的那句话已被删除。
2. *"高频类别跨数十个不同任务反复出现。"* 我们构造了它所要求的零分布——固定标签多重集，在各边之间置换标签，重算不同任务数（4,000 次置换）。观测值处于机会水平：`Fuse` 16 个不同任务，对照 16.03 的零分布均值（第 66.8 百分位）；`PrecisionChange` 13，对照 14.26（第 15.5 百分位）。因此跨任务复现**并未**由这个样本确立，第 2.5 节的可迁移性论断在此失去它的经验支持。它仍然是一个假设，需要第 4 节用一个不设每任务边数上限的设计去检验。

**存活下来的是什么。** 两件事，而且它们是承重的那些。

* **相对于一个忠实描述的压缩。** 对照同一批 55 个 diff 的联合粗粒度描述符（hunk 数 × 改动行数分桶，24 个单元格），标签分布耗 2.67 比特对 4.26——一个 1.6 的因子——同时只用 10 个类别来命名程序做了什么。单一的低基数摘要更便宜（仅 hunk 数：2.49 比特），但它们不是对改动的*描述*；它们只是它的一个投影，而第 3.6 节表明它们不携带超出其自身粒度的信息。
* **不靠强制分类的覆盖。** 当 `Other` 被主动招引、且每个 `Other` 都被要求解释为什么十一个具体类别全都失手时，仍有 90.9% 的边落进冻结词表。一个必须被吹胀才能吸收其数据的词表，本会表现为一条带着异质理由的 `Other` 长尾；我们实际得到的，是五个指向同一个缺失类别的、一模一样的拒绝。

两个结构性事实也仍然成立：`WarpReduce` 与 `SharedMemoryTransform` 在一个只有 Triton 的语料库里不可观察，而它们恰恰就是那两个从不充当主标签的类别——这是粒度被钉在所输出语言的抽象层上的证据。并且 **55 条边中有 0 条携带单个标签**，这就是为什么 54.5% 这个多区域数字无法区分"一个动作、若干处位置"与"若干个动作、各一处位置"。第 2.2 节把它提升为论题中心的跨位置属性，在这份数据上是*不可辨识（unidentifiable）*的；我们把它作为对第 4 节的一项设计义务来陈述，而不是作为一个发现。

### 3.6 结果：有信息量的检验，以及一次颠覆我们标题结论的更正

低熵本身并不有趣，而本节初稿恰恰论证的就是这一点：对同一批 diff 的粗粒度*表层*描述同样低熵（hunk 数 2.49 比特；改动行数分桶 2.40 比特），所以如果为坐标系变更辩护的论据是"变换能被压缩"，它就已经被数 hunk 给证伪了。所需要的，是一个检验：语义标签是否携带着关于*结果*、而表层结构不携带的信息。

把相对父节点的实测加速比取四分位作为结果（\(H = 2.00\) 比特，4 个单元格），并询问每个描述符能解释其中多少。原始互信息（mutual information）偏向于单元格更多的描述符，所以这个比较必须经过校准。初稿把它校准错了。

**这个错误。** 我们的 Miller–Madow 校正被以 \(\hat H = H_{\text{plug-in}} + (k_X-1)/2n\) 的形式施加到一个条件熵上，而那是*边际*熵的偏差项。plug-in 互信息估计量的偏差是 \((k_X-1)(k_Y-1)/2n\)；在 \(k_Y = 4\) 下，初稿欠校正了一个三的因子，而且它对 10 单元格标签描述符欠校正得远少于对 24 单元格粗描述符。它还只把语义描述符对一个同基数的零分布做置换，从未对粗描述符给予同样的处理。所报告的结论——"语义标签产生的信息少于表层结构（0.615 对 0.728 比特）"——是那套算术的一个副产物。

**经过校正的检验。** 我们现在以三种方式估计互信息，并对称地校准两个描述符，固定描述符、置换结果（20,000 次置换，种子 20261002）。

| 描述符 | 单元格数 | MI plug-in | MI Miller–Madow | 零分布均值 | 零分布标准差 | 置换 \(p\) |
|---|---|---|---|---|---|---|
| 主语义标签 | 10 | 0.697 比特 | 0.624 比特 | 0.397 | 0.072 | **0.0005** |
| 粗粒度 diff 结构 | 24 | 0.937 比特 | 0.792 比特 | 0.990 | 0.085 | 0.752 |
| 仅 hunk 数 | 9 | 0.367 比特 | 0.276 比特 | 0.361 | 0.071 | 0.436 |

这颠覆了初稿的发现，而且这次颠覆不是一个偏好哪个偏差公式的问题：在无公式的置换检验（permutation test）下，语义标签远高于它自己的零分布（\(p = 0.0005\)），而粗描述符观测到的互信息却*低于*它自己的零分布均值（0.937 对 0.990）——它那个看似更高的原始数字是对 24 个单元格的过拟合，其中 11 个只含一条边。我们也报告诚实的配重：配对 bootstrap 差 \(\mathrm{MI}_{\text{label}} - \mathrm{MI}_{\text{coarse}}\) 为 \(-0.361\) 比特，95% CI 为 \([-0.689,\,-0.034]\)。在未校准的口径下粗结构仍然胜出；我们主张未校准的口径是错误的口径，但这个数字留在那里，给任何不同意的人。

**那么这为论题买到什么？** 比它看起来要少。一个超出其自身粒度来预测结果的标签，是关于这个语料库的一个真实结果：一条成功边所做了之事的语义描述，携带着关于它赚了多少的信息，而它的 diff 形状不携带。但这里的结果是一个未归属的加速比比值，落在 55 条边上，其中 53 条同时改动了自动调优配置（第 3.7b 节），由我们未曾重新计时的语料库元数据测得，落在一个我们已证明无法估计分布的样本上。它是去运行第 4 节的一个论据，而不是第 4 节的一个替代品。

**我们保留下来的方法论教训。** 我们自己的完整性工具断言了 69 条数值论断并逐条通过（该工具现已承载 112 条，吸收了下面的更正），随后认证本节可复现。它比较的是*论文数字*对*脚本输出*，从不比较*脚本方法*对*有效方法*，所以它恰恰对这一类错误在结构上是盲的。流水线的验证阶段在参考文献里发现了三个真问题，在统计里一个都没发现。这就是第 4.4 节所警告的同一个失效模式，从一个想不到的方向到来：工程验收不等于方法论有效性，一张对账表不等于同行评审。因此我们把抓住这个错误的评审阶段，当作一个流水线无法自我生成的组件来看待，并把这一事件记录在第 7.5 节。

第二起校准确理事件属于同一类。一位审稿人报告了 CUDA Agent 全文 [1] 中一句逐字的话，支持我们批评的一个更强版本。我们无法复现那次检索——该预印本不提供 HTML 渲染，且只有 v1 存在——因此我们没有采纳那段引文，并相应地弱化了我们自己的论断（第 1.1 节）。一个自动化评审阶段会为其被指派去攻击的立场编造证据，而作者必须以施加于任何其他来源的同样纪律去核实它的引文。

### 3.7 两个我们未曾预料到的发现

**(a) `Other` 是一个单一的、系统性的缺口，而不是噪声。** 五条 `Other` 边都是同一个决策：别再自己实现这个操作，把它交给一个库后端——`x.matmul` / cuBLAS、`F.scaled_dot_product_attention`、`F.mish`、`F.linear`。它们包含样本中两个最大的实测加速比（相对父节点 327× 和 69×）。冻结词表描述的是*如何重构一个程序*，却没有一个槽位留给*到底要不要自己实现它*。

我们要小心不要过度兜售这一点。选一个库调用而不是一个手写内核，不是什么晦涩的洞见；那些在注释里记下"重活 GEMM 用 cuBLAS"的智能体系统，做的正是一个动作空间的设计者多半会纳入的东西。这个发现实际证明的东西更窄、作为警告更有用的是：**一个凭内省拼起来的动作词表，错过了它自己数据里回报最高的那个决策，而预先登记的数值阈值（25% `Other`）没能察觉，因为那些拒绝是同质的。** 任何去枚举一个变换空间的提案，都应当恰恰针对这一失效模式来检验——通过度量那些拒绝是关于*什么*，而不是它们有多少个。

**(b) 自动调优污染了几乎所有东西。** 55 条边中有 53 条共同改动 `@triton.autotune`——加上它、删掉它、重写候选列表，或改变缓存键。在这个语料库里，结构性变换与超参数搜索在经验上不可分离，有两个后果。就归属而言：一个声称来自 `Fuse` 的加速比，与一个同时被改动的启动配置相混淆，而我们的标注器一再记录下的正是这种无法指定一个主因的无力（只有 14 条边被标为高置信；38 条中等、3 条低）。就方法而言：任何建立在这种轨迹之上的动作级信用分配方案，必须首先*把自动调优从动作空间里剥离出去*，否则它会学到两样不同东西的混合。这不是一个新要求——CuAsmRL 在构造上就把自动调优与调度搜索分开 [30]——但一个从源码 diff 检视中设计的词表会悄无声息地违反它，因为 `num_warps` 和 `num_stages` 看起来像启动参数、写起来像代码。

一个相关的完整性说明：55 条边中有 9 条显示出相对父节点 10x 以上的改进，其中至少两条的父节点本已大致处于参考速度（`fast_p` 接近 1.0）。一个 MCTS 搜索语料库里巨大的相对增益，可能是病态父节点或计时方法论的副产物，而不是优化能力的证据，而我们没有尝试去审计计时流水线。

### 3.8 对前提的裁定

前提问题的回答是：**就存在性而言是"是"，就我们想从它那里继承的两个属性而言是"否"**。

* **存在性（supported，支持）。** 成功的调度级优化能被压缩到一小组反复出现的带类型词表上：10 个类别，在一个被主动招引的 `Other` 之下仍有 90.9% 的覆盖率，2.67 比特对 4.26 比特（后者是对同一批 diff 的一个忠实粗描述）。而且这些标签不是一个装饰性的划分：它们超出其自身粒度来预测实测加速比的四分位（\(p = 0.0005\)），而 hunk 结构做不到（\(p = 0.752\)、\(p = 0.436\)）。
* **跨任务可迁移性（not supported，不支持）。** 不同任务上的复现在标签置换零分布下处于机会水平（第 3.5 节）。抽样设计对它设了上限，我们**撤回**这一论断而不是含糊其辞。
* **跨位置协调（unidentifiable，不可辨识）。** 在 55 条边中有 0 条携带单个标签的情况下，多区域统计量无法把一个分散动作与若干个局部动作区分开。驱动整个形式体系的那个属性目前处于未被测量状态，而非已被证实。
* **词表的完备性（在一处被证伪）。** 一个缺失的决策——后端选择——吸收了每一个拒绝，而本为抓住这一情况而设计的数值红线没有触发。
* **未触及搜索或学习。** 第 3 节里没有任何东西涉及一个策略去选择任何东西。第 1.4 节的 L2 与 L3 论断原封未动。

一个想凭第 3.6 节拒斥整个纲领的读者是越界了；一个凭第 3.5 节接受它的读者同样越界。数据所支持的，是一个变换词表是对既往成功的一个*真实、有信息量、不完备*的描述——而这恰恰是使第 4 节值得被规约、而非可有可无的那种状态。
