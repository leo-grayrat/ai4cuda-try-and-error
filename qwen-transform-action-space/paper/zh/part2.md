## 4. 一个可证伪的实验框架

### 4.1 必须被击败的那个混淆因子

这个领域里最诱人的那个伪结果是："让模型在写代码之前先做计划，准确率就提升了"。这对动作空间什么也没确立。它可能只是平常的 plan-first 行为，或者干脆就只是更多的推理 token。任何无法把"规划有用"与"这一种特定的规划表征有用"分离开来的实验都不该被运行，因为它的阳性结果会被误读。

### 4.2 五个条件

| 条件 | 接口 | 它度量什么 |
|---|---|---|
| **Direct** | 生成优化后的整个内核 | 基线 |
| **Free-plan** | 写一份自由文本计划，然后生成内核 | 规划本身的价值，以及模型已经在做的任何隐式抽象的价值 |
| **Structured-action** | 从一个冻结的 `A` 中选取参数化变换，然后实现它们 | *外化出来的结构*在净去规划之后的价值 |
| **Oracle-action** | 供给正确的变换；模型只需把它实现出来 | 是策略还是实现构成了那个约束性瓶颈 |
| **Brute-search** | 枚举一个已知的变换空间、用一个学出来的成本模型给候选排序，循环里没有 LLM | 一个选择变换的 LLM 是否添加了自动调优所无之物 |

Free-plan 是多数已发表的"分解任务"类论断所省略的那个对照。Oracle-action 是让框架自我终止的那一个。Brute-search 之所以存在，是因为针对这整个纲领的那个最强反驳——一个在已知调度空间之上、带成本模型的精工程化枚举，已经能找到一个 LLM 被要求去命名的东西（第 5.3 节）。若那个枚举已经足够，那么搬动动作单元就毫无必要。这一反驳无法由其余四个条件裁定，因为它们每一个都把 LLM 留在循环里；而缺了这个臂，协议永远只能把*LLM-in-the-loop*接口的各变体相互比较。

有两个先行系统占据了这张表声称要区分的几个位置，因此协议必须据此来读。K-Search 已经*"显式地把高层算法规划与低层程序实例化解耦"*，并报告在 FlashInfer 内核上相对最先进进化搜索平均 2.10x、在复杂 MoE 内核上高达 14.3x [29]——那是一个被实现出来的、带阳性结果的 Structured-action 条件。CuAsmRL 在一个由 SASS 调度变异构成的显式动作空间之上训练强化智能体，并在构造上把自动调优与调度搜索分开 [30]。所以第 4 节不是一个关于系统的提案；它是一件用来*独立证伪*那类系统级结果的工具，办法是供给那些系统彼此之间没有跑过的那些对照。

关于第四行的又一点告诫：轮次级切分（第 2.1 节）在内核 RL 里早已存在，其中轮次级信用归属被报告为是重要的 [32]。Structured-action 必须击败*轮次级*分解，而不只是 token 级生成，否则这份抽象就是重复付费。

### 4.3 判读树

对每一种结果模式的预先承诺解读。结果在留出任务上度量，成功率与搜索代价（rollout 数、token 数、到第一个既有效又快于父节点之内核的墙钟时间）都予以报告。

| 观测 | 结论 | 后果 |
|---|---|---|
| Free-plan ~ Structured-action > Direct | 规划有用；结构什么也没加 | *此处无论文*；放弃抽象论断 |
| Structured-action > Free-plan > Direct | 带类型的动作空间提供了额外的归纳偏置 | 核心阳性结果；推进到学习层实验 |
| Structured-action > Direct 但 ~ 轮次级分解 | 增益来自层级，而非来自类型 | 重新瞄准到智能体轮次之上的信用分配 [32]，而不是到一个词表 |
| Oracle-action >> Structured-action | 抽象有用，但*选择*才是瓶颈 | 重述为一个动作之上的策略问题；`Q(P, a)` 成为被研究的对象 |
| Oracle-action ~ Direct | 告诉模型该做什么并没有帮助 | *该方向已死*：策略/实现分离什么也不买，因此没有任何动作空间能帮上忙 |
| Structured-action < Free-plan | 被强加的粒度本身就在主动地造成伤害 | 调查耦合：好的优化也许并不分解 |
| Structured-action ~ Brute-search | 相比带成本模型的枚举，一个 LLM 什么也没加 | *系统社区已经拥有这个问题*；改换目标或撤回 |
| Oracle-action 无法运行 | `φ` 无法为该任务族构造出来 | *不确定——不要读作零结果*（见下） |

Oracle-action 与第 4.5 节的实现义务都要求 `φ : ΔP → a`，即那个从一处改变中恢复出意图变换的映射；第 7.3 节承认我们从未构造它。一个决定性分支依赖于我们尚未造出之对象的协议，会在该对象不可得时报告"该方向已死"，那是一个装扮成严谨的假阴性。因此 Oracle-action 带一个显式前置条件：一个在留出集上经过验证的 `φ`，或一个代替它的人工供给预言、并把这次替代记录下来。若二者皆不可得，该分支*不予评估*，而论文的结论必须照此说明。

最后两行正是我们认为这个框架值得写下来的原因：它能输，而输是有信息量的。

### 4.4 词表冻结与留出协议

在轨迹的一个划分上构建词表，**冻结它**，然后检验从既往成功中抽象出来的动作是否对未见内核有帮助。把同样的边作为标签喂回去不是迁移，那是对答案重新贴标签。

这一纪律是对一种我们近距离观察过的、存在于本研究领域的失效模式的直接回应。当一个困难概念进入问题，最省力的动作是换成一个可编码、可度量、可签字的代理，然后让工程的完备性掩盖原问题仍原封未动这一事实。具体到内核优化的信用分配工作，那道阶梯是这么走的：研究问题 → 实验基础设施；"我们怎么在代码里找出那个重要优化" → "给定一个 A/B 结果我们怎么分摊信用"；"理解程序意义" → 一个手写的 AST 与正则分类器，把答案悄悄编码进了它的规则里。一项产出了基准、索引和协议、却从不重新打开原问题的研究，产出的是基础设施，应当被如此描述。

我们对每个实验所运用的操作性检验是：

> **如果这个实验完美地完成，它会改变关于原研究问题的哪一个判断？**

如果答案是"工具更好了"或"记录更可复现了"，那么这项工作是基础设施，不得被呈现为进展。第 3 节通过了这个检验（它改变了关于词表存在性的信念，并经由 3.6 改变了关于熵论证是否成立的信念）。构建一个动作空间 schema 与验证器则不会，所以我们不去构建：一件改变不了本文任何判断的工具，无论写起来多便宜，都不该出现在本文里。

### 4.5 预先登记的混淆因子对照

援引第 3.7 与 3.6 节，第 4 节的任何实例化都必须添加：

1. **自动调优隔离。** autotune 候选集在所有条件之间以完全相同的方式固定，或被显式建模为一个单独的动作维度。缺了这一点，比较就是在"结构"与"结构加超参数搜索"之间进行，而那是错误的对比；我们 55 条边中有 53 条在构造上违反它（第 3.7b 节）。CuAsmRL 通过在自动调优*之后*而非联合地进行调度，提供了一个可行先例 [30]。这一对照在实践中有两种失效方式，二者都产生误导性结果：钉住候选*列表*并不钉住被选中的配置，于是各臂仍可能落在不同的块大小上；而为了让列表可共享去缩小它，可能一次性把每个臂都压到地板，制造出一个虚假的零结果。
2. **结构匹配基线。** 纳入一个以等长、*带结构但无语义*的格式做计划的条件（例如用任意内容填满固定槽位），好让"它是一个模板"与"它是一种语义"无法被混为一谈——这是第 3.6 节表明为必要的那个对照。
3. **实现义务。** 对每个被选中的动作，报告随后的编辑是否真的触及了该动作所要求的各处位置。一个被选中却未被实现的动作是一次选择失败，而非一次编码失败，二者必须分开计数。
4. **留出泄漏审计。** 核实用于构建词表的任何任务都不出现在评估中，且词表在两者之间未经编辑。
5. **可分解性压力测试。** 抽样若干多类别共现的边（我们 55 条中有 38 条正因如此而为中等置信），检验联合选择是否胜过按次顺序选择。这是对第 7 节那条耦合反驳的直接检验。

### 4.6 这个框架不能被用来主张什么

即便一场干净的 Structured-action 胜利，也只确立*搜索*论断。那个*学习*论断——一个变换之上的策略比一个 token 策略更省样本——需要在模型匹配、轨迹匹配、终端奖励匹配的条件下，只改动信用目标来做真正的训练比较。我们这里没有那样的基础设施，任何观察性研究都无法替代它。

## 5. CUDA 之外的意义

### 5.1 编辑基与变换基的代码优化，比一个干净的区分所暗示的更接近

最近的邻居是那些学习做出性能改进型*代码编辑*的系统 [4,5,31]、把编辑*格式*当作一个训练决策来对待的系统 [6]、以及从仓库历史学习程序演化的系统 [7]。那个三分区分——带类型语义、跨位置协调、跨任务词表复用——比证据所能支持的更干净：它的三条腿中有两条撑不过第 3.5 节的那次测量，所以诚实的立场更窄。

真正可区分的、以其真实强度陈述出来：

* **相对编辑级工作 [4,5,31]。** AEGIS 把慢→fast 对分解为可复用的*原子编辑* [31]，PIRE 学习函数级的性能编辑 [4]。二者都是操作级的，且没有一个*是带类型的、其参数的实现义务在若干处位置之上被定义的*。我们的贡献不是那个想法而是那次度量：我们问一个固定的 12 类带类型词表能否在不被吹胀的情况下覆盖真实的成功边，结果它能（90.9%，且其残差的同质性我们作为一处缺陷而非一次成功来报告）。
* **相对变换级系统 [29,30]。** 新颖性论断不得不收缩最多的就是这里。K-Search 解耦算法规划与程序实例化，并在"需要协调的、多步结构变换"的内核上取得大增益 [29]；CuAsmRL 在 SASS 调度变异之上定义了一个显式 RL 动作空间，甚至用它自动地浮现优化招法 [30]。然而二者都没有报告*在公开轨迹上、针对一个冻结词表的覆盖率度量*，也都没有报告第 3.6 节那种零分布校准。我们剩下的论断是那个描述性论断，加上那套能够证伪其阳性结果的协议。
* **相对格式级工作 [6]。** AdaEdit 表明，在准确率匹配时，被输出的表征能把时延与成本改变 30% 以上。这支持"坐标系并非中性"这一总体形状，但它是一个关于*成本*的论断；我们的必须是关于*归纳偏置*的，那更强、且只有靠干预才可检验。
* **相对轮次级分解 [32,35]。** Kevin 为 CUDA 内核按智能体轮次归属奖励，报告正确性 56%→82%；更宽的信用分配文献如今已把在段与步的粒度上工作当作常态 [35]。该领域已经从 token 往上走了一层。一个变换词表必须在*它*之上挣得自己的存在价值，这就是为什么第 4.2 节如今把轮次级分解纳入为一个对照点，而不是把 token 级生成当作唯一基线。
* **相对泛化的 plan/动作统一 [33,34]。** 有两个智能体一侧的结果在此作出了一个关于表征的论断，而它们对我们不利。CodeAct 把 text/JSON 工具调用替换为可执行的 Python，作为一种*统一动作空间*，并报告跨 17 个模型高达 20% 的更高成功率 [33]——这是"动作表征并非中性"的直接证据，也就是我们论题的那个形状、只是去掉了它的内核专属性。ReCode 走得更远，索性把规划与行动之间的边界整个溶解掉，把高层 plan 当作占位函数、以动态粒度控制递归地展开为原语动作 [34]；那在另一个领域里，接近第 4 节的 Structured-action 条件。二者都不关乎 GPU 内核，二者都不冻结一个带类型的变换词表，二者都不报告这样一个词表能否覆盖真实的成功优化，而且——至关重要的是——二者都不运行第 4.1 节所坚持的那种 Free-plan 对照。诚实的解读是：我们第 4.3 节那个分支 `Free-plan ≈ Structured-action ⇒ 此处无论文` 是一个相邻领域也尚未解决的鲜活风险（live risk），而我们的新颖性收窄为：第 3 节那个描述性度量、那套证伪纪律，以及只有这个领域才会逼出来的那些内核专属混淆因子对照（自动调优隔离、后端替代）。

* **相对一个在实践中已然存在的、被命名的变换词表 [1]。** 最强的那个现有系统，已经恰恰在用我们这套词汇——只不过以散文形式——指示它的模型。它的技能文件按预期收益给优化排序——优先级 1 算法级（>50%）：为减少访存而做的内核融合、为复用而做的共享内存分块、访存合并；优先级 2 硬件利用（20–50%）：向量化的 `float2/float4` 载入、warp 级的 `__shfl_sync`/`__ballot_sync` 原语、按块大小与寄存器做的占用率（occupancy）调优；优先级 3 微调（<20%）：指令级并行、FP16/TF32 混合精度、预取与双缓冲——并附上一份检查表，涵盖以 padding 规避 bank conflict、循环展开、WMMA/MMA 张量核心、persistent kernel 与 CUDA Graphs。它甚至规定了我们做信用分配所需的那个"写下预期收益"的习惯：在实现之前先 "Document expectation: 'Fusion will eliminate 3 kernels, expect ~20% speedup'"。这对一个新颖性论断是坏消息，对那个前提却是好消息：一个交付了本领域最强公开系统的人，早已相信优化行为可以被描述为一小组、有排序、被命名的程序变换。那个系统*没有*做的，是把这份词表变成学习或搜索的接口：被枚举出的那些名字待在一段提示里，策略仍然在 token 之上被训练，那些层级是建议而非带实现义务的带类型参数，也没有人测量过那份检查表究竟覆盖了真实的成功优化、还是仅仅听起来对。我们的第 3 节就是那次测量，而第 4 节针对的，正是它们的设计所没有触及的那一部分。

一个不依赖我们词表之正确性的、更锐利的真实差别表述是：编辑级、轮次级与 plan 统一方法从*接口*取它们的单元（一个 diff、一次工具调用、或一次递归函数展开恰好是什么），而变换从*程序的性能模型*取其单元（硬件实际执行时会怎样不同）。那是一个干净的区分，而它也恰是这一区分之所以危险的原因——性能模型恰恰是一个 LLM 最不该被假定拥有的东西。

### 5.2 分层 RL 对此有一个名字，也有一条警告

时间抽象是老技术：options [11]、option-critic 架构 [12]，以及 Voyager [14] 这类 LLM 智能体里的技能库。我们的 `a = (τ, ℓ, θ)` 就是一个带参数的 option。这条谱系带来两样我们应当继承而非重新推导的东西：一是在子策略之上的策略那套形式机器，以及一份坦率的、关于*更高层动作何时不奏效*的文献。近期关于 option-critic 病态的工作报告了策略坏死与冗余覆盖——学出来的 option 从不被使用、或彼此重叠到分层什么也买不到 [13]。正是这份文献，让我们在第 4.3 节坚持预先承诺负面与不确定分支，而不只是一个"赢"的分支。我们自己的结果不应被读作这些病态的一次预演，而把它那样读是一次错误：在第 3.6 节那个未经校准的比较里，语义标签未能在预测力上超过表层结构，那会是"更高层什么也买不到"的一个轻度实例。经过校正的校准颠覆了那个发现（第 3.6 节），所以这里的分层既未被我们的数据确证、也未被证明冗余——它恰恰仍然是 [13] 与第 4 节所关于的那个开放问题。

### 5.3 编译器谱系同样是一条警告

Halide 把调度从计算里分离出来 [8]；TVM 学会了在调度变换之上搜索 [9]；Ansor 在张量计算的因子分解上搜索 [10]。这些系统早就把程序变换当作优化工作的单元。由此有两条教训。

第一，这个想法并不新，任何新颖性论断都必须落在 LLM 接口上，而不是落在一个变换空间之存在上。第二，也是更重要的，我们的论题与编译器的实践之间存在一处未解决的张力。自动调优系统有意*不*要求程序员给变换命名：它们枚举一个空间，用一个学出来的成本模型去搜索它。如果那已经找到了调度，那么一个在选择变换上的 LLM 必须添加成本模型所缺的东西——处理空间中没人写过枚举的那些部分。那是一个真实的、有真实可能被证伪为假的假设，而它是我们所知的、针对这一方向的最强反驳。

我们最初的四个条件没有一个能回答这一反驳：四个都把一个 LLM 留在循环里，于是协议永远只能给自己内部的变体排名。补救是结构性的而非修辞性的——第 4.2 节添加了一个第五臂 **Brute-search**（枚举加学出来的成本模型，不带 LLM），第 4.3 节添加了它的判读行：如果 Structured-action 与 Brute-search 在统计上不可区分，那么系统社区已经拥有这个问题，本纲领应当改换目标或者撤回。注意这是一个我们预期*难赢*的检验：在一个良规定的调度空间之上做一场胜任的 Ansor 式搜索，是一个令人生畏的基线 [10]，而一个 LLM 在这里靠"更有表达力"什么也挣不到。

编译器这个类比还掩盖了一处更深的不对称，而它是整个论题里最薄弱的那个环节。在汇编、IR 与一门高层语言之间，坐着编译器：那是一些实际上就是全函数的关系，于是一层抽象可以被*删掉*并被有信心地重新推导出来。Sul 与 Ré 自己那一版的退休论证恰恰依赖这一点，而他们坦率地给这桩交易命名——“我们接下那桩交易，是因为编译器比我们更常是对的”[36]。然而，在一个被命名的变换与它的代码之间，坐着一个 LLM，而关系 `a → ΔP` 是一个随机映射，不是一个函数。本文里每一样把一个变换当作对象来对待的东西——包括那个驱动它发问的信用分配——都继承了那道缺口。两个后果随之而来：实现一个被选中的动作是一个*一等失效模式*，而不是一个实现细节（这正是第 4.5 节对照 3 要求把它单独报告的原因），而摘要里那个反方向的 `φ : ΔP → a`，并不比正方向那个更有存在的保证。如果实现者不可靠，那么无论词表拟合得多么好，一个变换级动作空间都什么也买不到，而这恰恰是第 4.3 节 Oracle-action 分支被设计来捕捉的那个结局。

### 5.4 智能体技能设计是同一个问题换了身衣裳

一个相关的争论涉及那些附加在编码智能体上的长自然语言指令文件（技能）。存在这样的系统：它们强制模型在写代码之前先输出一个结构化的中间表示——一个带声明的持久状态与标注数据边的分层图——然后让一个确定性审计器去检查它 [28]，并把非常大的、手工维护的指令文件随方法一起发布。

我们自己的两个方法论观察可平移到那个设计上，且二者都未被度量。第一，在实践中定量要求压过定性要求："产出十张图"容易满足，"每张图都携带信息"则不然——所以一个被要求*做计划*的智能体会产出计划形状的文字而非决策形状的文字，而这恰恰是 Free-plan 对照存在的理由。第二，随着一个指令文件的增长，遵从性似乎会退化，直到没有单条规则能被可靠地遵守。如果 structured-action 条件被实现为一份冗长的、关于变换类型的大白话目录，它会同时继承这两个问题，而 Free-plan 可能出于注意力预算而非语义的原因打败它。这支持第 2.3 节那个小的带类型接口，而不是支持文档——而第 4.5 节对照 2 才是会去检验第二个主张而非假定它的东西。

### 5.5 验证是一个前提，不是一个附录

第 4 节里的每个实验都要求一个可信的正确性与计时预言，而这在 GPU 内核基准里不是一个已解决的问题。被报告的失效包括数值上错误却通过检查器的内核 [20]、在变异测试（mutation testing）之下自身就弱的基准预言 [24]、以及在更严格的测量下活不过针对真实工作负载、或针对 PyTorch 之验证的结果 [22,23,25]。对抗性加固工作从另一侧把这个环闭合 [19]。hacker-fixer 循环让三个智能体交替——一个试图在不解决任务的情况下通过验证器的黑客、一个修补验证器以拒绝每个被发现漏洞的修补者、一个确认被修补的验证器仍容许合法解的求解器。审计五个终端智能体基准上的 1,968 个任务，它发现 323 个（16%）在只给定任务描述时对前沿模型是可被攻破的；在 KernelBench 上，它在一个公开报告之漏洞的留出语料上把攻击成功率从 62% 压到 0%，而一个*更弱*的模型运行这个循环能抵御明显更强的黑客（76% 与 61% 的攻击率被降到 0%）[19]。

与动作空间相关的那个观察是我们的而非他们的，但它直接从那个设定推出：如果候选选择按原始测得的加速比给提案打分，一个虚假的 100x 漏洞在数值上会压倒一个合法的 1.5x 改进，于是搜索在*任何*验证器被咨询之前就被偏置向那个漏洞。因此给奖励设界或归类，不是基准卫生，而是变换级信用分配的一个结构性前提——否则一个按动作索引的价值函数会学会偏好那些结构上不成立、但数值上响亮的变换，而那个抽象会把脆弱性进口进来而不是修好它。

### 5.6 训练底座批评

最后，这里的框架暗示了对围绕长时程智能体 RL 的不稳定性文献的一种不同读法。公开记录里有一处值得一说的张力。一方面，CUDA Agent 陈述：尽管有很强的通用编程性能，LLM 在内核生成上仍竞争不过 `torch.compile`，并据此为大规模 RL 以弥合那道缺口提供动机 [1]。另一方面，一个 CUDA 内核里的大多数 token 只是普通编程 token——`for`、`if`、`float`、`int`、`*`、`[]`、`+`——只有一小撮、高度模式化的少数派才是 CUDA 特有的，所以一个关于"为什么 token 级训练在这个领域会*异常*不稳定"的语料频率解释，从第一性原理上很难维持。而这个解释也并不是以"能把它算作 CUDA 结果"的方式领域特定的：一个目标领域在预训练中有多稀有——一门冷门编程语言、一种硬件描述语言、一种形式化证明语言——都应当产生同样的低概率尾部。如果一个解释对每个稀有领域都成立，它就不可能是关于 GPU 的任何东西的解释。在那种读法下，低概率尾部爆炸更像是长多轮工具使用的一次训练—推理不匹配与分布外上下文问题——吞下编译错误、剖析器转储、奇异的中间程序状态——而不是关于 CUDA 语法学习理论的一个陈述，这与"训练—推理不匹配、而非领域稀有，才是让 LLM 强化训练不稳定之物"这一普遍发现相一致 [26,27]。

我们有意不去断言围绕这场争论流传的那些具体基座模型精度数字：它们出现在我们无法对一手来源核实的二手写作里（第 1.1 节），而训练期可观测量并不公开 [1]。因此上面的论证是一个*框架性*论断——token 级接口是那种不稳定性与那个信用问题的一个貌似合理的共同原因，因为它强迫同一个策略在同一个序列里既建模程序结构、又建模具噪音——而不是一个经验论断。

## 6. 相关工作

针对各集群的定位已在第 1.1 节与第 5.1–5.6 节论证；本节只记录哪些工作属于哪个集群、以及我们从中取什么。

**智能体 RL 与 CUDA 生成。** KernelBench [2]；CUDA Agent，我们框架所指向的那个系统——我们读的是它的源码，而非转述它的摘要：它在一个由工具定义的环境内部训练一个 token 级 PPO 策略，而那个环境的动作空间是 Edit/MultiEdit 一类的操作，并且它在自己的技能文件里随附一份按优先级排序、被命名的优化检查清单 [1]；CUDA-L1（在执行反馈上做对比排序）[16]；Dr. Kernel（为 Triton 设计奖励）[17]；CudaPerf（来自合并访存、占用率、算术强度与同步的结构奖励，在 token 级）[15]；NKI-Agent（在 AWS Trainium 上跑的 CUDA-Agent 配方，带一个负面 GRPO 结果）[18]；Kevin（多轮 RL、轮次级奖励归属）[32]。我们的批评瞄准被记录的学习接口，而不是一个被断言的 token 级动作空间（第 1.1 节）。

**轨迹之下的信用分配。** 一个按信用粒度——轨迹、段、步、token——组织起来的 69 篇论文综述语料库，带一个可识别性分析，表明仅文本的历史甚至能让信用的*符号*都不可辨识 [35]。这是我们第 1.2 节必须对照着来读的那个集群：该领域在更细的粒度上对信用重新加权，同时把动作单元留在 token 上。

**LLM 智能体中的动作表征。** CodeAct 把一个智能体的动作合并为可执行的 Python，作为一种统一动作空间，并报告高达 20% 的更高成功率 [33]；ReCode 递归地统一规划与行动，把 plan 作为占位函数、在动态粒度控制下展开为原语动作 [34]；Voyager 把习得的技能作为可复用代码持久化 [14]。这些是"坐标系并非中性"最强的通用证据，也是离我们 structured-action 条件最近的通用类比（第 5.1 节）。

**程序之上的变换级与编辑级搜索。** 最约束我们新颖性论断的那个集群：K-Search，显式解耦算法规划与程序实例化，报告平均 2.10x、在 FlashInfer 内核上相对进化基线高达 14.3x [29]；CuAsmRL，一个在显式 SASS 调度变异动作空间之上的 RL 智能体，也自动地浮现优化招法 [30]；RAS/AEGIS，用检索到的慢→fast 样本与可复用的*原子编辑*做束搜索 [31]；从 77k 个 C++ 提交对中策展出的性能改进代码编辑，在一个全系统模拟器中评估以控制计时噪声 [4]；编辑序列的神经模型 [5]；软件演化之上的 RL [7]；以及"被输出的编辑格式在成本上并非中性"这一发现 [6]。第 5.1 节陈述剩下的那点差别。

**编译器搜索空间。** Halide 把调度与计算分离 [8]；TVM 在调度变换之上学习 [9]；Ansor 搜索张量因子分解 [10]。第 5.3 节解释了为什么这条谱系既是我们的血统、也是我们最强的反驳。

**分层 RL 与技能发现。** Options [11]、option-critic [12]、被报告的 option 病态——策略坏死与冗余覆盖 [13]——以及 LLM 技能库 [14]。我们的 `a = (τ, ℓ, θ)` 是一个带参数的 option（第 5.2 节）。

**基准完整性。** 正确性幻觉 [20]、对内核基准预言的变异分析 [24]、对抗性 hacker-fixer 验证器加固 [19]、合约级验证 [21]，以及针对真实工作负载或针对 PyTorch 的更严格验证 [22,23,25]。这些对任何第 4 节实验的约束，都比对本文任何其他部分的更多（第 5.5 节）。

**智能体 harness 与技能。** 在代码之前被输出、被确定性审计的结构化中间表示，随非常大的指令文件一起发布 [28]（第 5.4 节）。

**轨迹数据。** AdaExplore，一个失败驱动、保多样性的搜索方法，公开它的父—子树 [3]。在此被用作关于优化行为的数据；本文没有运行任何形式的搜索基线。

## 7. 局限与开放问题

### 7.1 机器标注的循环性，以及什么才能真正控制住它

这个问题所需要的对照，是由人来读三十到五十条真实边，理由很具体：词表是否存在恰恰就是待答的问题，而发明词表的那个实体不该同时成为判定数据是否贴合它的那个裁判。这里的标注是自动化的。后果不可避免：标注流程与类别系统出自同一个模型家族，于是一个 `Fuse` 判断可能是关于标注器描述习惯的一个陈述，而不是关于代码的。

仅这样声明本身不是一个对照。我们把那些会使之成为对照的验收标准写出来，好让那道缺口是可度量而非修辞的：

1. **对同样的 55 条边做独立的盲法人工标注**，由至少两名并非词表作者的标注者进行，报告 Cohen's $\kappa$ 或 Krippendorff's $\alpha$。在 $\kappa$ 未被报告时，"10 个类别覆盖 90.9%"与"标注器几乎什么都能命名"无法区分。
2. **从一个不相交的来源自底向上构建词表**——由一个不同的家族（人或模型）从语料库的留出一半上开放编码归纳出类别、冻结，然后检验预先登记的词表是否被恢复。是收敛效度，不是自洽。
3. **第 3.6 节在共识标签上存活。** 置换结果是本文关于标签的主要定量论断；如果当标签来自人的共识而非来自单个模型家族时它就消失，那么这个论断属于标注器，而不属于程序。这是那个决定性检验，而我们没有运行它。
4. **标签可得而不词表可得。** 只给标注者十二个名字，不给我们的定义、示例或参数槽，以降低类别*语义*被构造性地共享之可能。

标准 2、3、4 已被执行，测量结果列在下面；标准 1（一次真正独立的、最好由人来做的第二遍标注）尚未执行，而它仍是本文最主要的那项未决要求。

**无定义盲重标（标准 4）。** 一个独立的标注器在只看见那十二个光秃秃的类别名——不给定义、不给参数槽、不给示例、不给判定规则——的条件下，重新标注了同样的 55 条边。它与原始那一遍的一致度相当可观：原始一致率 74.5%，Cohen's $\kappa = 0.687$。有三个类别完全没被那一遍盲标使用（`WarpReduce`、`SharedMemoryTransform`、`HostDeviceOverlap`），而这一点对第 3.5 节那个"Triton 抽象层"解读的贴合，胜过对一次标注失败的贴合。

**头条是否存活（标准 3）？单靠它自己并不存活。** 把第 3.6 节那个置换检验改用盲标签重算，得到互信息 0.451 比特、$p = 0.106$——不显著——而被告知定义的标签给出的是 0.697 比特、$p = 0.0005$。把范围收窄到两遍标注一致的那 38 条边，显著性得以恢复（互信息 0.664，$p = 0.0016$）。因此，这份词表的有信息量程度，部分是那次诱发（elicitation）的一个属性：给出定义会把标签磨利成一个能预测结果的东西，而我们还无法把"其中多少是程序里的结构"与"其中多少是我们提供的引导"分离开来。标准 1——真正独立、最好由人来做的人工标注——仍未执行，而它是唯一能把二者分开的那个检验。据此，第 3.6 节已被改以这个更弱的强度来陈述。

**自底向上的开放编码（标准 2，部分）。** 一个无法访问冻结清单的编码者，从与已标注样本任务不相交（任务零重叠；见随文提供的开放编码记录）的 24 条成功边上，归纳出 7 个类别。被恢复出的那个空间，可辨认地是同一片领地——工作/布局重映射、精度体制、初始化提升与缓存、流水线阶段重构、后端改派、代数改写、冗余数据搬运消除——并带有两处信息量丰富的分歧。该编码者把启动常数的调整严格置于次要地位（19 次共现、0 次主类），这暗示我们的 `ChangeLaunchConfig` 把数据所视为"伴随"的东西过度切分了；而该编码者独立地重新发现了后端改派，也就是我们被迫塞进 `Other` 的那个类别。那是关于*空间*、以及关于我们清单上一个洞的收敛性证据，而不是关于所取十二个名字的收敛效度——因为编码者与词表仍共享同一个模型家族。

我们确实采取的两项纪律措施值得记录，因为它们部分地约束了标注器：`Other` 被明确招引，且每个 `Other` 都必须为拒绝全部十一个具体类别给出理由（后端选择缺口正是这样浮现的），以及置信度分布是被报告而非被隐藏——14 高、38 中、3 低，也就是说本文多数标签是它自己的标注器都不确定的标签。

### 7.2 我们关不掉的三个危险

我们把这些列为本文自己的终止条件，每一条都被第 3 节的那次测量磨得更锐。

**（1）好的优化也许不能被离散地分解。** 一次强劲的内核重写常常是一次*整体设计*的改变：块大小取决于布局，布局取决于线程映射，线程映射又与共享内存足迹和占用率联合决定。把这强塞进一个动作*序列*，可能恰恰毁掉那个产生胜果的联合搜索，而事后分解成 `Tile + Fuse + Vectorize` 可能是诠释而非解释。这个语料库里的证据：多标签边是常态，而标注器最常坦白的就是把加速比归因于一个动作之不可行。开放问题：在一个参数向量上做联合选择会不会胜过按次顺序选择，若不会，分解本身是不是正确的那一层？（第 4.5 节对照 5。）

**（2）模型也许已经私下做这个抽象。** 如果一个大语言模型在无需被告知的前提下就在内部表示"用一个 warp 归约"，那么把动作外化可能只是*打印*出本来就在发生的推理，什么也没减少。这正是 Free-plan 对照存在的理由，也正是形如 `Free-plan ~ Structured-action > Direct` 的结果必须被报告为一个零结果的理由。我们没有办法以观察的方式把它定下来。

**（3）选择也许很容易而实现才是瓶颈。** 告诉一个模型"用 warp 级归约"，可能仍然让它写不出一个正确、快速的实现。如果那是常见情形，那么高层动作就不是那个约束性瓶颈，而整个纲领把难度放错了位置。Oracle-action 条件存在的目的恰恰是暴露这一点，而它的中性结果是这个研究方向预先承诺的终点。

### 7.3 抽样、归属与度量限制

被标注的 55 条边是一个多 hunk 富集的有偏样本，无法估计总体标签频率。**入选闸门本身是从语料库继承来的：每条边都以基准自己的 `correctness == true` 为条件，而我们引用的两篇论文论证这个预言会容许假通过 [20,24]。因此第 3.4–3.6 节建立在一个我们已给出理由去不信任的过滤器之上，而一个变异加固过的预言可能根本改变哪些边算作成功。** 相关的度量缺口：">5% 更快"阈值没有噪声底，因为计时取自语料库元数据且从未重新测量；`fast_p` 的基线约定未经审计；55 条边中有 9 条显示相对父节点 10× 以上的增益，其中至少两条的父节点本已接近参考速度，所以被用作第 3.6 节结果的一些实测加速值很可能是计时副产物；55 条边中有 53 条在改动结构的同时改动自动调优，因此第 3.5–3.7 节的逐动作归属在构造上被混淆。轨迹语料库是由一个*搜索*过程而非由一个从奖励学习的策略产出的，所以被访问程序的分布不是一个第 4 节实验会面对的 on-policy 分布。最后，`φ` 在本文中从未被构造——我们断言这些 diff 有标签，而不是断言存在一个从 diff 到标签的机械映射——而这两者之间的缺口是一个我们有意不去开的独立研究问题（自动动作识别）。

### 7.4 语言依赖性

第 3.5 节最干净的那个负面结果关乎我们自己的设计：两个类别不可观察，因为 Triton 藏起了它们所居的那个抽象层。因此一个变换词表不是一个语言中性的对象。它被钉在模型被要求输出的那种东西的抽象层上，而"CUDA 优化"至少横跨三个层（CUDA C++、Triton、高层框架图），每一层有不同的自然词表。任何迁移论断除非规定了层间映射，否则必须是层内的。

### 7.5 本文没有证明什么

没有搜索实验。没有训练。没有新模型。没有任何度量上的改进。第 3 节是一个经过校准的、关于描述的"存在且不充分"结果；第 4 节是一个尚未被运行的协议。标题有意是一个问句，而第 3.6 节有意是我们对自己给它之答案的一次更正。

## 8. 结论

我们追问：智能体强化学习系统用于 GPU 内核优化的 token 级动作空间是不是一个错误的坐标系，而带参数的程序变换 `a = (τ, ℓ, θ)` 对于搜索与学习是不是一个更自然的单元。答案是：*前提成立，我们为之构建的两个论据不成立*，而这个问题在经验上仍然开放。

**前提成立。** 公开的成功优化轨迹能被压缩到一小组反复出现的带类型词表上。在横跨 45 个任务的 55 条被标注 MCTS 边上，12 个冻结类别中的 10 个在一个被主动招引的 `Other` 之下覆盖了 90.9% 的边，代价是 2.67 比特对 4.26 比特（后者是对同一批 diff 的一个忠实粗描述）。更重要的是，这些标签不是一个装饰性的划分：在对称置换校准下，语义标签对于实测加速显著有信息（plug-in 互信息 0.697 比特，偏差校正后 0.624，$p = 0.0005$），而粗粒度 diff 结构（$p = 0.752$）与仅 hunk 数（$p = 0.436$）都没有胜过它们自己的零分布。它受到一个对照的界定：在不给定类别定义的条件下对同样的边重新标注，会让同一个检验变得不显著（$p = 0.106$，对照 $p = 0.0005$；两遍标注在 74.5% 的边上、于 $\kappa = 0.687$ 的一致度上一致），于是这部分效应里，有些是由词表诱发出来的、而非在程序里被发现的（第 7.1 节）。我们报告的是那个更弱的版本。

**我们为之构建的两个论据不成立。** 第一个是压缩本身，以一个 5.78 比特的 diff 指纹熵为对立面来呈现：在 55 个两两互不相同的指纹下，那个量恒等于 $\log_2 55$，而"没有任何类别曾两次产生同一个 diff"这一论断对任何标注都成立。两者都被撤回。第二个是跨任务复现，它在标签置换零分布下处于机会水平（`Fuse` 观测到 16 个不同任务，对照 16.03 的零分布均值），因为我们的抽样对每任务的边数设了上限。因此第 2.5 节的可迁移性论断不为这份数据所支持，而驱动整个形式体系的跨位置协调属性在此是*不可辨识*的，因为没有一条边携带单个标签。

两处撤回互不减轻对方；校准与更正的依据见附录 B。

**这个问题仍然开放，如今有了一个更锐利的形状。** 观察性证据无法裁定一个关于干预的论断，而接口层的问题已经被那些比我们更早到达那里的系统部分回答了：K-Search 解耦规划与实例化，报告 2.10x–14.3x 的增益 [29]；CuAsmRL 直接在一个显式调度变异动作空间之上训练 [30]；Kevin 按智能体轮次归属奖励 [32]。因此第 4 节规约了一个五条件协议——Direct、Free-plan、Structured-action、Oracle-action，以及一个带学出来的成本模型、循环里没有 LLM 的 Brute-search 臂——它的判读树把中性、反向与*不确定*分支预先固定，包括"若一个在选择变换上的 LLM 胜不过枚举就撤回该方向"那一支，以及那个在 `φ` 无法构造时防止一个假阴性被报告为零结果的前置条件。

两个进一步的、来自尝试证伪我们自己的发现应当走出这个具体主题。第一，每一条我们无法分类的边都是同一个未归类决策：别自己实现，去调用一个库。一个凭内省拼起来的动作空间错过了它自己数据里回报最高的动作，而本为恰恰检测这一情况而设计的预先登记数值阈值没能触发，因为那些拒绝是同质的——这是一个警告：覆盖百分比是检测一个缺失类别的错误工具。第二，在 55 条成功边中，自动调优在 53 条里与程序结构一起移动，所以在现实的内核优化语料库里，超参数搜索与结构变换若不被有意分开设计就并不可分离；任何为代码提出动作级信用分配的人都应当假定这个混合，直到被证明并非如此为止。

于是，那个窄的贡献是：对一个前提的一次经过校准的度量、对我们最初所依赖的两项支持统计量的一次明确撤回、以及一个能裁定那次度量所不能裁定之物的协议。我们愿意捍卫的那个更宽论断远远超出 CUDA：在为某个抽象是一个更好的坐标系辩护之前，先确立它胜过一个由其自身粒度构成的零分布、而不是一个它够不着的天花板，查一查你的词表悄悄漏掉了哪个决策，并且不要信任一个从未被要求去质疑一种方法的验证工具。

## 附录 B — 生产记录

本附录记录第 3 节背后的分析在早期版本中曾被怎样陈述，以及本轮自动化评审阶段能证明与不能证明什么。它放在附录而非正文，是因为它关系到上述数字应被赋予多少分量，而不关系到关于动作空间论证本身。

这三项不是文体上的忏悔；三者都改变了我们对上述结果的信念，且三者都直接关乎这个领域正在就自动化科研提出的那个方法论论断。

**（1）一个验证工具可以数值上周全而在方法论上失明。** 我们的完整性阶段跑了 69 条从原始数据重新导出的断言，在 69/69 全部通过的同时，第 3.6 节的标题性统计结论却是错的。它比较*论文数字*对*脚本输出*，从不比较*脚本方法*对*有效方法*；一处被误用的偏差校正会在其中完美地传播，因为它所核对的数字正是那个 bug 产出的数字。同一个工具还忠实地认证了一个如今被第 3.5 节识别为恒等式的图。这就是第 4.4 节所警告的那个失效模式——内部严谨性在上升而问题原封未动——在我们自己的质量闸门内部、而不是在别人的基础设施里被复现。对任何自我报告的流水线的实际后果是：对账检查必须与至少一个能质疑*方法*的检查配对，在我们这个案例里那是那个对抗性评审阶段，而我们本可以排进日程的任何自我评审都无法替代它。

**（2）我们自己的检索失败，被记成了别人的造假。** 一位审稿人逐字引用了 CUDA Agent 源码里的一句——"these tools define the action space of the agent"（这些工具定义了智能体的动作空间）——来支持我们那个批评的更强版本。我们无法复现那次检索：该预印本只有一个版本、没有 HTML 渲染，于是我们把那段引文判定为编造，把它删掉，并相应地弱化了第 1.1 节。而那段引文是真的。后来我们把 arXiv e-print 作为一个 LaTeX 源码包取回并读它时，那句话逐字就在那里，连同那份工具清单，以及论文自己关于其 PPO 动作 $a_t$ 就是 token 的陈述。

这次的失败不是轻信，而是反方向上的一次范畴错误：我们把"我无法检索到这种格式"当成了"这无法被核验"，随后又施用了一条看上去保守的规则——丢弃不可核验者——而它恰好丢弃了一个*真实、且对我们不利*的论断。对任何会作引用的流水线，有两点后果：一条被拒绝的引文，在其被删除之前，应当先换一条渠道重试（源码存档、备选站点），因为格式受限并不是证据不可核验；而且错误的方向值得注意——一条只会"削减有利于论文的主张"的政策会系统性地漏报，而这一次它删掉的恰是准确的料。我们的第 1.1 节如今是从源码写就，而非从摘要写就，而这次更正本身，就是我们想要留档的一部分。

**（3）一个来自同一个模型家族的五席位评审团，是一位审稿人，而不是五位。** Sul 与 Ré 的博客里有一句旁白，读起来像是关于本文自己那道质量闸门的一个预言：一场多智能体的“三方审查”是个说得通的架构，但没有任何东西保证这三位审稿人在检查不同的东西，而他们可能收敛到同一个盲区 [36]。我们的第 3 阶段评审团恰恰是那个形状——五个不同的授权，一个认知家族——而我们同时观察到了好处与失效。两位审稿人独立地发现了那个被此前四个自查阶段认证过的统计错误，那是单个审稿人无法提供的佐证，仅这一点就使评审团成为正当。但*人格*上的评审团多样性不是*来源*上的多样性：就事件（2）的证据而言，一个席位编造的引文就是全部五个席位编造的引文，而在单个模型家族内部再怎么贴角色标签，都替代不了一位外部审稿人。我们保留这个五授权结构，因为它找到了真问题；而我们拒绝把它描述成独立评审。
