# `2_1` 八条本机正确修改的源码阅读记录

本文件只按父子源码描述 **可能的程序决策** 和依赖关系。逐边正确性和单轮筛查见 [prospective-screen-2_1.md](prospective-screen-2_1.md)。筛查速度不是动作贡献证据；除单独记录的 `11→47` 预注册候选外，下述改动还没有有效的撤销计时。

| 父→子 | 从代码看到的改动 | 后续定位/对照价值 |
| --- | --- | --- |
| 8→11 | `_relu_add_bias_kernel` 从全张量线性索引改为每通道空间块，host 网格、kernel 索引、bias 标量读取与参数列表一起变化。 | 一项跨多处代码的共同决策；差异块很多，但不应按行数算成多个独立动作。 |
| 8→16 | 改为每个 `(N,C)` 程序循环处理空间块，同时调整网格、参数和一项 warp 配置。 | 主要布局/循环为共同决策；配置或可单独查，但需先验证依赖。 |
| 11→47 | 就地写回、二维变三维网格、缩减自动调优配置，以及 bias 连续性整理。 | 多项可分别构造的决策和一个普通可执行对照；测量前判断已在 [2_1-11-47-premeasurement.md](2_1-11-47-premeasurement.md) 封存。 |
| 51→53 | 原本按 `(N,C)` 每程序循环处理空间并就地写回；子版本改为按空间块并行、另分配输出，并引入多配置自动调优。 | 布局、输出策略、配置集合可能分别检查；多个改动也可能交互。排在 11→47 之后。 |
| 53→140 | 主要改变自动调优配置范围和数值；kernel 重命名、表达式拆开与注释变化看起来保持同一寻址和计算。 | 可用于检验把大量文本差异误认成结构优化的情况；实际性能需复测。 |
| 148→150 | PyTorch 的 ReLU 加偏置后处理整体换为一个 Triton 通道×空间块 kernel，新增相应启动与输出。 | 清楚的整体实现替换，但父子间缺少可独立区分的多项动作；适合作为单决策检查。 |
| 168→170 | 每程序从单通道空间块改为通道×空间二维块，配置空间随之改变；host 侧还有按需连续化 bias/x 的变化。 | 通道分块及配置相互依赖，需要先界定共同动作；连续性代码可能成为普通可执行对照。 |
| 199→200 | 每程序从单行空间块改为多行×空间块，扩大配置集合，grid 随 `BLOCK_M` 改变。 | 行分块、配置和启动须一并审阅，避免把配套代码拆成多个独占提速的行。 |

这八条都属于同一个卷积加逐元素后处理任务；不能拿它们冒充八个独立任务，也不能据此声称逐元素、归约、矩阵三类都已验证。`11→47` 第一轮对照时，同机 GPU 还运行课程视频转写任务，逐次延迟大幅波动；该轮性能数据留存但判为不可用于归因。原始回复/token 仍不可得。
