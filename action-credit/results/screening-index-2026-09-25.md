# 前瞻筛查清单与任务划分

这份清单在新的跨任务 GPU 筛查之前生成。输入为 AdaExplore Level 2 归档，SHA-256 `14e31f73af3491cff486ce25f08c48e08f0a042816539abe3bb9541841b39cc5`。运行 `python -m scripts.index_credit_edges .cache/adaexplore-l2.tar.gz runs/credit-screen-index-l2.json` 得到完整逐边表；该文件留在忽略目录，SHA-256 `bdb0f53c82e0dc5b3b02b7ea8d505dad0226bf890d24873f0d83b4a680b05536`。

清单按任务编号和子节点编号升序，没有使用档案速度排序。全部 18,581 条显式父边中：

| 归档筛查状态 | 数量 | 含义 |
| --- | ---: | --- |
| `root_parent` | 953 | 父节点是根节点，不进入父子正确优化修改集合 |
| `archived_incorrect` | 8,629 | 父或子未被档案标为正确 |
| `different_device` | 6,037 | 档案中的设备编号或设备名称不一致 |
| `identical_source` | 144 | 正确、同设备，但源码完全相同 |
| `eligible` | 2,818 | 只满足归档筛选；仍需本机正确性及多改动检查 |

这些状态依次判定，因此每条边只在表中出现一次。归档 `eligible` 绝不等于本机有效，也不说明它提速。

## 开发与留出任务

为了不让已看过的案例进入留出集，任务 `2_1, 2_9, 2_12, 2_14, 2_18, 2_20, 2_29, 2_40, 2_55, 2_56, 2_59, 2_63, 2_68, 2_76` 固定为开发任务。其余任务按 `SHA256("code-credit-v1:" + task)` 的第一个字节模 3 划分：余数为 0 划入留出，其余为开发。100 个 Level 2 任务中，最终 68 个开发、32 个留出。划分只由任务编号决定，与档案或本机速度无关。

留出任务固定为：`2_2, 2_7, 2_11, 2_15, 2_21, 2_22, 2_24, 2_28, 2_34, 2_36, 2_38, 2_45, 2_48, 2_50, 2_52, 2_53, 2_58, 2_62, 2_65, 2_66, 2_70, 2_74, 2_80, 2_81, 2_82, 2_85, 2_86, 2_87, 2_88, 2_89, 2_95, 2_100`。同一任务的所有父子修改一并留出。先在开发任务中按完整清单顺序筛查；留出任务在方法冻结后才作方法比较。此前已经看过的旧案例只记历史开发记录。

Level 2 题目多为组合运算，逐元素、归约和矩阵类别须根据题目和实际优化对象逐案记载；归属不清保持 `other`。若某类找不到足够本机有效的多改动案例，报告数据来源限制，不靠重新命名类别达成配额。
