# 原文派生材料核对决定

独立审阅读取了原始全文、优化稿与 C01—C45 映射，未接触任何保留题候选结果。研究者逐项回看原文后修订如下。

- C23 恢复为每轮实施前记录预期效果或收益，删除优化稿额外增加的“为什么会有帮助”义务。C25 恢复“测量并分析，以理解变化”，最终说明中明确解释的义务来自所有条件共有的说明契约，不冒充原文要求。
- C16 保留架构相关编译、原 Linux 示例的 sudo 和共同 Windows 命令映射。原文第 6 节本来就要求编译架构匹配 GPU，不能把写死 9.0 当成跨设备的固定研究要求。
- C28—C32 的边界、同步、类型、内存安全与数值稳定性位于原文 Correctness Checklist (Always Verify)，标记为要求。C28 恢复验证数组访问和线程范围的原意，C32 保留处理 NaN/Inf 以及具体诊断动作。
- C43 补回具体的症状与补救方式，保持适用条件，不将它缩成泛泛的“调查”。C11 按原绑定示例保留 float32。C26 用原有的先 1—2 轮、再 3—5 轮阶段表述。
- 额外回看时，恢复了原文对三类优化优先级的影响范围说法，并明确归于来源；也保留原文 1.0/0.95/0.8 ms 的最低与目标示例。这些是原文陈述，不是本研究实测结论。
- 不接受 C01 的“延迟不等式改变判据”意见：原文成功标准明确写有 <=0.95× baseline，并非只有一个偶然例子。保留该判据，同时写清最低目标与继续优化的区别。
- 不将 C21 的命令降为可选示例。原文 Key Reminders 直接要求 Pass config parameters，另有代码示范；它没有“可选”限定。Requirement 标签表示原文明示义务，不代表它与禁令具有同样措辞强度。
- C04 同时保留允许 cuBLAS/GEMM、cuDNN/Conv 和 Conv/ConvTranspose 使用 cuDNN 的要求，不把它用于本研究不存在的卷积案例评分。

修订后仍为 45 个来源条目，27 项要求、14 项条件建议和 4 项示例实践；所有九个原始代码或工作区示例在派生版本中保持一致。仅格式化版的非空白词序与原文一致。这里记录内容核对，不能替代后续任务效果证据。
