Ruling: 先使用同一透明工具循环完成开发试跑，再冻结正式运行器。现有 CLI 提供任意 shell 时，文件写权限难以只改变一个因素。统一工具循环固定读写、编译、验证、计时和提交能力；权限分组改变写入是否被拒绝，检查器分组改变提交是否被拒绝。代价是结果首先适用于这套工具工作流，需要在报告中明确。

Ruling: 原始文档中“无限继续优化”和正式实验的共同预算同时出现时，以共同实验预算终止运行，并将未完成情况作为结果。不能给长文档额外资源，也不能删掉原文中要求继续优化的段落。当前开发配置为最多 24 次模型请求、32,000 个生成 token（含 API 计入的推理量），工具单次 180 秒。累计输入用量实际记录，不声称已强制输入与输出合计的固定 token 上限。

以该实际失败为输入，规则维护模型原样保留旧文档，补写了 34 行、21 个列表条目。合并文件从 376 行增加到 411 行。未强制行数、未人工扩写凑长度。两次规则生成尝试及成本均已归档：首次 8,192 生成 token 全用于推理、没有正文；提高生成上限后使用 8,677 token 并完成追加。第一次失败也进入维护成本。
