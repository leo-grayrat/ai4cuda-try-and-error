## 保留题和执行机制的物理验证

四道保留题与两道新开发题均已准备，Model 类与固定版本 KernelBench 原文的语法树一致。LayerNorm 和 GEMM 链保留原始名义尺寸。Softmax 初稿误把宽度缩到 4,096，现改为保留 393,216 列，只将批量减为 128；另有 393,217 列边界案例。Sigmoid 同样只减少批量。当前 12 组保留配置的 GPU 基线与非默认 stream 均通过。

Ruling: 超宽 Softmax 保留原始逐元素容差，同时补充概率和、逐行 L1 分布误差检查，并写进共同契约。逐元素 atol=1e-2 对极小概率会接受全零或错误稀疏分布；这两类实际反例均被补充检查拒绝，真正的 torch.compile 输出通过三组分布检查。

真实 CUDA 示例与 cuBLAS GEMM 已跑通权限和提交门槛：写固定参考被拒绝；没有编译、验证和计时的提交被拒绝；合法结果通过六项独立验证后可提交；再修改 Python 文件会使验证与计时过期，但不要求重编译未改变的 C++/CUDA 文件。跨进程 GPU 锁已验证互斥与释放，后续 GPU 执行串行。

任务清单曾将规范化换行的文本哈希误记成实际文件哈希，Windows CRLF 导致不一致。已分开记录实际字节与规范化文本的哈希，确认修正前后模型文件字节未变，并让源材料和任务文件在 Git 中保留字节。

## 顺序门槛与重复规模条件
