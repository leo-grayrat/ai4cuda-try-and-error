# 重复告诫的规模条件

自然追加序列仍按真实开发回合继续。另设置受控重复条件：从第五次累积快照的实际追加部分取出完整文本，按原有顺序完整重复，不制造新失败，不改写为新要求，也不靠空行或断行凑长度。

| 条件 | 实际行数 | 文字 token | 追加部分总份数 |
| --- | ---: | ---: | ---: |
| 第五次自然快照 | 541 | 8,069 | 1 |
| 一千行以上重复条件 | 1,045 | 22,124 | 4 |
| 三千行以上重复条件 | 3,061 | 78,344 | 16 |

第五次快照的 93 个追加列表条目已映射，但包含同义重复和复合义务，不等于 93 项独立要求。重复条件没有新增来源条目，更不能把 1,488 次列表出现记成 1,488 项新要求。两份长文均以第五次自然快照的原始字节开头，完整复制过程及文件哈希在 `repeat-pressure/manifest.json`。

实际 API 已接收两份输入，计入共同封装后分别为 22,152 与 78,372 输入 token，原始请求和响应在 `evidence/repetition-input-probe-01/`。这一步只检查输入是否能送入模型；后续同题任务运行测量重复负担、遗漏与成本。官方文档列出的上下文容量为 [1M token](https://api-docs.deepseek.com/quick_start/pricing/)。

这组条件回答的是同一批提醒被反复重申的效果。真实失败驱动的规则增长，继续由自然快照之间的比较回答；两种来源在图表和结论中分列。
