# 哪些提醒交给了执行机制

这里记录正式对照将切换的实际能力，避免把“有检查器”理解成全部要求都已执行。所有条件都有相同的工具接口和独立评测；权限条件另行拒绝越权写入，检查器条件在模型请求提交时检查并反馈。

## 当前正式比较：原始 skill 及其处理版本

正式条件以 `protocol/v1/manifest.json` 为准，未采用旧追加材料中的 G 条目。只从优化稿删除 C05—C07 三条显式固定文件提醒；其余原文义务和九个示例保持。以下是当前执行能力，不能从“加了检查器”推定其他义务已完成。

| 原文要求或共同工具能力 | 当前执行 | 独立审阅仍需判断 |
| --- | --- | --- |
| C05—C07 固定文件 | 权限条件拒绝越权写入、删除；所有条件最终检查哈希 | 工具接口权限不构成原生代码的操作系统沙箱 |
| C08—C09 候选路径与结构 | 权限条件限制写入路径；检查器检查必要文件存在 | 代码中实际计算的归属与文件职责 |
| C02—C04 计算与库限制 | 部分静态检查；验证阶段拦截候选 forward 内已知 PyTorch 计算 | C++ 计算与库调用的语义、未走到的路径 |
| 最后版本的编译、验证、计时记录 | 检查器要求对应当前文件并遵守顺序；失败使对应记录及后续记录失效 | 这是当前工具执行机制，不把旧 G 条目当作正式文档新增要求 |
| C12、C14—C15、C44 接口、参数、stream 与正确性 | 所有条件使用相同独立测试 | 测试范围之外的输入与实现性质 |
| C27 清理 | 检查器覆盖部分旧版、测试文件名 | 未编译备份、正常文件内的诊断函数和中间实现；未提交时另记完成时点尚未到达 |
| C23、C25、C45 预期、分析与命名 | 没有语义强制门槛；工具保存可选 label 与可见说明 | 改动前的预期、解释与证据关系、模型自己使用的测试名称 |
| 所有条件共同的最终说明契约 | 不机械评分文风 | 是否交付、完整连贯的叙述、证据对应及失败陈述 |

## 探索阶段的历史覆盖表

下表保留早期 G 条目的来源联系，供查阅旧探针和材料；这些不是正式文档条件，也不扩展当前实验范围。

| 要求及来源 | 实际执行 | 覆盖范围与后续审阅 |
| --- | --- | --- |
| 不改参考与固定基础设施，C05—C07 | 权限条件拒绝写入或删除；所有条件独立比对固定文件哈希 | 是所提供工具的写入权限，不是任意原生代码的操作系统隔离 |
| 候选放在规定文件中，C08—C09 | 权限条件限制写入路径；检查器要求存在 CUDA 文件、绑定与 ModelNew | 文件存在不证明所有计算都放在正确位置，仍审阅实现 |
| 禁止 Python 端张量计算，C03、G04-05 | 提交时检查已知调用与直接输入运算；验证时实际拦截不允许的 PyTorch 运算 | 静态检查不覆盖所有别名；执行检查覆盖测试实际走到的路径 |
| 最后文件须通过编译、验证和计时，G01-07、G02-03 等 | 对比原生源码与完整候选哈希；重新编译清空后续记录，重新验证清空计时记录，失败清空相应通过记录 | 检查的是当前文件内容和通过顺序；不是“任何同内容写入都必须重跑”的字面动作计数 |
| 保留正确的参数、数值、stream 和历史输出，C12、C14—C15、C44、G05-01 | 独立验证固定形状、随机种子、参数、重复调用、非默认 stream 与旧输出 | 通过给定案例不证明所有可能输入与并发情形；未测范围不记成已证明 |
| 清理中间版本与探针，C27、G05-08—G05-09 | 检查器识别部分旧版/测试文件名 | 不保证识别嵌入正常文件的诊断打印、无用分支或语义上多余的代码；这些仍独立审阅 |
| 工具字段与错误分类，G01-17—G01-21 | 字段类型与操作枚举在所有条件中检查，作为可用工具接口的共同基础 | 没有强制执行“工具失败后必须读取文件”；不能把协议本身算成某个实验条件的收益 |
| 保留已知正确回退、停止投机调优，G01-05、G03-09—G03-10 | 未由提交检查器执行 | 从轨迹核对；不因有检查器就删掉这些要求 |
| 解释预期、测量变化及文风，C23、C25、共同说明契约 | 未机械执行 | 隐去条件后逐段引用证据审阅；不按字数、标题或句长阈值给分 |
| 原因推断、时钟解释及引用计数经验，G04-09、G05-03 | 未自动判断真假或适用性 | 核对实际来源；压缩时保留原说法，另行记录证据质量 |

## 真实流程验证

`evidence/mechanisms-03/` 保留原生 CUDA 示例和 cuBLAS 探针的实际结果：参考文件写入被拒绝；没有验证记录的提交被拒绝；编译、验证和计时完成后可提交；再次验证使先前计时失效，补做计时后可提交；修改 Python 候选使验证和计时失效。四个新增回归案例还复现了旧检查器错误接受后续失败与倒序验证的问题，修正后完整测试为 45 项通过。

只有明确覆盖的提醒才适合在“保留机制、删除提醒”的条件里删除。一个原文列表条目常把验证、回退、预算和清理写在一起；不能因为其中有一句能检查，就删掉整个条目。该对照须逐句记录删除范围，保留未机械覆盖的义务。
