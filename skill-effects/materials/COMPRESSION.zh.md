# 累积文档的压缩对照草稿

`growth_compression.json` 按原始条目整理合并文本，`prepare_growth_conditions.py` 生成前五个阶段的压缩文件。每份文件的开头均逐字节保留原始 CUDA skill，包括全部代码示例。只压缩本研究后续追加的文字。

| 追加阶段 | 原文 token | 压缩稿 token | 整份文档减少 |
| --- | ---: | ---: | ---: |
| 1 | 4,307 | 3,895 | 9.6% |
| 2 | 5,164 | 4,314 | 16.5% |
| 3 | 6,077 | 4,735 | 22.1% |
| 4 | 6,913 | 5,012 | 27.5% |
| 5 | 8,069 | 5,562 | 31.1% |

计数使用固定版本官方 tokenizer，针对文档文字；实际运行用量另行记录。原文 93 个列表条目均有来源位置与压缩段落对应，但一个列表条目可能包含多项要求，同义条目也可能重复。这不是 93 项独立要求的计数，更不是语义等价证明。

压缩保留了早期“所有修改后编译”与后期“原生文件改动才编译”的并存，也保留了没有时钟测量支持的原因解释。通过压缩同时修正这些内容，会把文字整理和规则修正混为一个变化。阶段映射还要检查是否提前引入后续新增信息。

材料目前为正式封存前的草稿。独立审阅已保存完整请求与响应；第一轮 32,768 个生成 token 全部用于推理，没有形成可审阅文本，作为失败保留。随后关闭推理模式重试，并回看原文处理了适用范围、阶段提前引入和例外边界的问题。审阅器也把第一阶段已有的 missing operation 误记为第四阶段新增，故没有照单接受。具体处理见 `evidence/compression-review-01/decisions.zh.md`；表中为修订后计数。
