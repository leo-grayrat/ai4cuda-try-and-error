# 重复试验的分析口径

本记录在批量刚启动、尚无终止样本时写入。控制器与任务保持冻结，以下只增加结果分析，不反向改变候选任务。

四问分别保留证据：增加要求比较 task_only、source_core、original；组织方式比较 original、formatted、phase4；机制比较 phase4 上的权限/检查器二乘二组合。source_core 与 full 同时改变具体内容、示例和数量，不解释为内容无关的纯规则数效应。排版与整理效果也分开。

共同交付先比较最终独立正确性、源码保护、独立测量完成、完整报告可得性。检查器接收不等于质量提高；被拒的完整报告也进入审阅。未写后端、候选失败、截断、报告缺失、API或控制器故障分别记录。全部计划样本的状态和成本保留，不只纳入成功者。API故障导致未启动的槽位不充当模型失败。

成本使用提供方实际usage：首次输入、累计输入、缓存命中、未命中、生成和思考分别列出。按照同一价格快照估算，并补全输入按未命中计价的缓存敏感性结果；不把文档缩短比例当作总成本下降。三路运行总墙钟与单轮时长之和分开。工具进程时长含等待，不能称作GPU内核耗时。

连接中断时，把已返回usage的已知估算计入全部尝试的成本合计，未返回响应的用量保持未知，并标记合计不完整；不把整轮已知消耗清零，也不补猜丢失用量。完整轮费用估算与仅观察到部分usage的估算使用不同字段。模型生成量中位数排除外部中断记录，原始中断消耗仍保留在总账。

程序性能只对有效候选解释，同时报告其在全部样本中的比例。最高通过测试档是离散且有上限的指标；触顶不推出真实最大速率相同。原测量将跨请求空闲包含在输出间隔，低负载smoothness检查需结合原始时间戳，不能直接称为计算退步。对原始记录做后续分解可增加解释，但不覆盖原判决。

要求遵循沿用69项来源核对单，按各条件实际提供内容和共同任务判断适用性。单卡不适用的多卡部署事项单列。不同片段重复传达同一要求须合并来源，未提供的要求不算违规。分别审阅真实图执行、解释与证据一致性、不同优化是否实际实现/测量、队列和失败记录；不拿文件存在或方案名称数量代替执行与语义证据。

思考原文与工具行动逐次对照，区分没有考虑、考虑后主动推迟、反复规划未行动、测量疑点、工具信息受阻、预算误解及实际纠错。主题来自文本审阅，不能由关键词数量直接判定。成功和失败、不同条件都要读；没有暴露某项考虑不推断完全没想过。提供响应文件、段落或工具事件索引，使结论可核查。

报告展示每轮点与每题重复，组内仅六轮，不作普遍可靠性结论。两项任务同属轻量因果特征处理，不能推广到任意仓库或大型模型部署。文献背景使用FlashRT的研究问题，旧CUDAAgent方案及结果不并入样本。
