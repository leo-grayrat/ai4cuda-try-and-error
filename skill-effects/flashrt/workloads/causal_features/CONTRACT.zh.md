# 因果特征任务约定

本任务由研究方提供参考和适配器，用于比较 FlashRT 说明原文及其处理方式。模型采用原库 `CausalConv1d`，固定权重种子 703，三层通道为 C→H→H→C，卷积核为 5、5、3，每层接 SiLU。固定计算本身是规范，无需训练或下载权重。

## 输入、状态与输出

一次请求提交 float32 的 `(C, T)` 特征序列，后端依配置的块长逐块输出。最后一块只返回有效长度。三层分别保存自己的卷积历史，不能在块边界丢失，也不能改成访问未来输入的运算。

同一会话连续请求等价于将其输入按时间连接，再执行整段因果网络。显式 reset 清除历史；重置后重复相同输入应重现第一次输出。一次只允许一个请求在途，消费完全部输出后才能提交下一个请求或 reset。

配置默认开发案例为 C=16、H=32、T=1043、块长127，覆盖末尾短块。较大案例为 C=128、H=256、T=16384、块长512。两者属于同一个任务，不是两个独立应用。

## 应用接口

`adapter.py` 是固定客户端接口。输入、输出及元数据使用原 FlashRT `SharedTensorBuffer`，控制使用原 `SharedControlBuffer`。控制码为 1 启动、3 重置、2 终止；适配器在重置后发送启动，支持原电平控制通道上的重复重置。

输出元数据为请求编号、块编号、有效长度。后端先发布数据，再发布元数据；适配器检查顺序、长度和覆盖，不能把通道自动跳过的旧数据当作完整输出。

参考启动方式为 `python -m causal_features.reference --repository <固定源码目录> --config <JSON>`，由运行工具配置模块路径和显式 GPU 编号。候选可以提供自己的后端脚本，接受相同两个参数，并保持相同 IPC 约定；独立运行工具通过 `--backend-file` 启动它。参考、适配器和研究方验证工具不能被候选改写。

## 验证与记录

`run_local_reference.py` 在 CPU 上执行整段网络作为数值对照，另起 CUDA 后端经适配器收取输出。六请求序列包含连续会话和重置复现；原输入、输出、日志、时间戳及执行代码快照留存。容差为 atol=3e-5、rtol=3e-4，用于允许 CPU/GPU float32 累加顺序差异，不允许更换计算含义。

`verify_local_ir.py` 再用原 `SequentialExecutor` 执行逐层状态图，直接与适配器捕获的参考输出比较。它使用相同输入及重置序列；结构校验与数值比较分开记录。

运行结束时验证后端退出，并检查本次随机前缀下的七个共享内存对象是否消失。故意中断接收也必须完成清理。原始标准错误输出保留；当前解释器启动时的一条固定路径提示单独记录，其他错误不能借此忽略。

当前工具保存首块、完成时间和每块接收时间。第一请求标为冷启动请求，后续请求另标；所有记录保留。有限请求的输出速率不等于最大可持续速率，正式性能比较还需加入稳定负载扫描。
