## 代码检查的边界

`flashrt/ir/graph.py` 提供结构校验；`executor.py` 的 `_ScopedStateStore` 限制未声明的 get/set。直接运行原执行器的四个 CPU 案例见 [实测记录](evidence/ir-state-probe-01.json)。

调用 get 取出可变对象后，原地修改不会经过 set 检查，源码对此已有注释。同时，`analysis.py` 对共享持久状态保守建立依赖，包括读取者。现有实测支持访问限制的具体边界，尚不足以推断实际应用存在错误调度或数值错误。

## 真实任务的运行条件

`docs/setup.md` 要求 Linux，并列出 CUDA 12.9+ 或 ROCm 7.2 等环境。现成应用涉及 WorldPlay、LongLive、LiveAvatar、Krea/SAM 和 Qwen3 Omni。仓库中的模型来源与配置包含约 5B、14B、30B 规模模型，部分部署跨多卡。

仅估算 5B 参数的 BF16 权重就约需 10GB 十进制存储，尚不含运行内存；这是容量估算，不能写成已实测 OOM。是否可以卸载、量化，以及这些改变是否仍适合原工作流，须另作验证。`apps/_template/reference/pipeline.py` 中的 TODO 和 NotImplementedError 表明模板不是现成顺序参考实现。

当前阶段未下载这些模型权重，也未将新造的小任务冒充原应用复现。先解决运行条件与任务匹配，再冻结新比较方案。
