### Importing from the shared runtime, IR, and adapters

Import as much as you can from the shared `flashrt/*` runtime
(see the "Resources you can use" section in the repo-root `AGENTS.md`),
from `flashrt.ir` for the IR framework, and from
`flashrt/apps/<app>/adapter.py` for the adapter class that drives your
test / benchmark harnesses. You do not need to import from
`flashrt/apps/<app>/reference/` at all — everything you need at runtime is in
the shared runtime, the IR framework, and the shared adapter. The
default is to *use* the shared abstractions, not vendor or
re-implement them: gratuitous copies of shared-runtime / IR / adapter
code into your variant create drift and silent inconsistencies. When
the shared runtime genuinely does not cover behavior you need, the
agent runs autonomously — there is no "stop and ask" escape valve —
and the path forward is one of:

- Vendor the offending shared file into the variant's directory and
  modify the copy, per the repo-root `AGENTS.md` Phase-4 rule
  "Read-only areas are not a blocker — vendor the file into your
  workspace".
- Re-implement against shared primitives, subject to the four
  constraints in the repo-root `AGENTS.md` "Multi-GPU coordination"
  rule (use sparingly, build on the shared substrate, preserve the
  implicit and explicit globals the rest of the codebase relies on,
  and vendor the new code under `flashrt/apps/<app>/backend/`).

Both paths require the on-disk audit / justification the linked
rules spell out. Neither requires user consultation.
