## What each file does

- **`graph.py`** — Core data structures you use to build IR graphs:
  - `IRGraph`: the top-level graph container (operators, edges,
    state objects, external I/O, preamble/chunk phases).
  - `IROperator`: a computation node **with an attached
    implementation**. Subclass it and override
    `execute(inputs, context, state) -> dict` (and optionally
    `should_run(context) -> bool`). The base constructor takes
    keyword-only metadata: `name`, `op_type`, `inputs`, `outputs`,
    `state_reads`, `state_writes`, `stream_mode`, `sub_graph`,
    `config`. A plain `IROperator(...)` call (without subclassing
    or overriding `execute`) produces a structural-only op whose
    default `execute` raises `NotImplementedError` — useful for
    scaffolding, not for running.
  - `IREdge`: a dependency between operators. Data edges carry
    tensors between ports. Ordering edges enforce execution order
    without data transfer (set both ports to `None`).
  - `StateObject`: a named persistent state (e.g., a KV cache).
    Its `scope` controls cross-chunk dependency analysis:
    `"chunk_persistent"` creates cross-chunk constraints,
    `"session_init"` and `"ephemeral"` do not.
  - `StateStore`: the `Protocol` an operator's `execute` receives
    as its third argument. Exposes `get(name) -> Any` and
    `set(name, value) -> None`. Both raise if `name` is not in
    the operator's declared `state_reads` / `state_writes`; this
    is the runtime check that keeps declared state dependencies
    honest (see "State access" below).
  - `TensorPort`: a named input/output slot with optional shape and
    dtype hints.
  - `OpType`: `BLACK_BOX` (opaque), `EXPOSED` (visible internals),
    `COMPOSITE` (contains sub-graph).
  - `StreamMode`: `BATCH` or `STREAMING`.
  - `StreamingInfo` / `StreamingPattern`: metadata attached to
    streaming edges.

- **`ops_base.py`** — `@ir_operator(...)` decorator. Wraps a
  function `fn(inputs, context, state) -> dict` into an
  `IROperator` subclass instance with all metadata baked in, so
  you can pass the decorated object straight to
  `graph.add_operator(...)`. Use this for one-off leaf ops; prefer
  subclassing `IROperator` directly when you need one class
  instantiated with many different parameters (e.g., one
  `DiTDenoiseStep` class, one instance per denoising step). The
  decorator also accepts an optional `should_run=lambda ctx: ...`
  for chunk-conditional ops.

- **`executor.py`** — `SequentialExecutor(graph)` that runs an
  `IRGraph` on a single device in topological order. Use this to
  validate your IR conversion in Phase 2. It takes only the graph;
  operator implementations live on the operators themselves. Key
  surface:
  - `init_state({name: value, ...})` — pre-populate persistent
    state before any operators run (e.g., empty KV caches
    allocated at session start). Preamble operators can also
    populate state by calling `state.set(name, value)` during
    `run_preamble`.
  - `run_preamble(external_inputs, context)` — runs the
    `preamble_ops` once per session.
  - `run_chunk(external_inputs, context)` — runs the `chunk_ops`
    once per chunk. Call it in a loop over chunks.
  - `context` is opaque — define it however your operators need.
    It is the right place for per-chunk scalars, model runner
    handles, and other session-wide helpers.
  - `state` is managed by the executor (in a dict it owns) and
    handed to each op through a scoped `StateStore` that rejects
    any access to names the op didn't declare.

- **`analysis.py`** — Tools the agent runs on validated IR graphs
  to discover optimization opportunities:
  - `analyze_cross_chunk_dependencies(graph)`: finds operators
    that share `chunk_persistent` state → cross-chunk constraints.
    Returns independent pairs → pipeline parallelism candidates.
  - `find_pipeline_stages(graph)`: partitions operators into
    stages by grouping shared-state operators. Each stage = one
    GPU.
  - `find_streaming_overlaps(graph)`: finds streaming edges with
    rate-conversion metadata.
  - `compute_critical_path(graph, latencies)`: longest dependency
    chain through one chunk.
  - `summarize_graph(graph, latencies)`: all of the above in a
    human-readable summary. **Start here.**
