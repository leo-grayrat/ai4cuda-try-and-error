## How to use this module

See the repo-root `AGENTS.md` section "The IR workflow" for the
full workflow. In brief:

1. **Phase 1**: Define your operators (subclasses or
   `@ir_operator`) in `flashrt/apps/<app>/backend/ir/ops.py`, then build
   `IRGraph` instances in `flashrt/apps/<app>/backend/ir/graph_builder.py`
   by inspecting the full exposed computation graph in the user's
   reference backend under `flashrt/apps/<app>/reference/` (the worker, any
   model pipeline(s), and their interactions).
2. **Phase 2**: Construct `SequentialExecutor(graph)`, pre-populate
   any externally-allocated state with `executor.init_state(...)`,
   run it with test inputs, and compare against the reference
   backend's output.
3. **Phase 2 continued**: Run `summarize_graph()` on the validated
   graph to discover pipeline stages, streaming overlaps, and
   independent operator pairs.
4. **Phase 3**: Use the analysis results to design deployment
   variants.

If you believe the IR framework is missing a capability you need,
work around it inside `flashrt/apps/<app>/backend/`. The agent runs
autonomously — there is no "ask the user" escape valve — and the
shape of the workaround is whichever of the two paths in the repo-
root `AGENTS.md` applies: vendor the offending IR file per "Read-
only areas are not a blocker — vendor the file into your workspace",
or re-implement against the existing IR primitives subject to the
constraints in the "Multi-GPU coordination" rule (build on the
shared substrate, preserve the globals the rest of the codebase
relies on, vendor the new code under `flashrt/apps/<app>/backend/`).
