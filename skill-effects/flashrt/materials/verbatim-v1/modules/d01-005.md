**`graph_builder.py`** constructs `IRGraph` instances that represent
the full exposed computation graph, using the data structures from
`flashrt.ir.graph`. You will typically build:
- A worker-level graph representing the high-level stage scheduling
  (which stages run, what data flows between them, which are
  streaming). This covers the worker and any black-box stages.
- One or more model-level graphs, one per exposed model in the
  pipeline. Each model-level graph represents the fine-grained
  operators within that model (e.g., individual denoising steps,
  VAE decode). A pipeline with multiple exposed models gets
  multiple model-level graphs.

Inside the builder, register `StateObject`s for every piece of
persistent state your operators will touch, instantiate the op
classes / decorator-bound op objects defined in `ops.py` (`g.add_operator(DiTDenoiseStep(k, ...))`,
`g.add_operator(text_encoder_prefill)`, etc.), wire edges between
their ports, and list each operator in either `preamble_ops` (runs
once at session init) or `chunk_ops` (runs once per chunk).
