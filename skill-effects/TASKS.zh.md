# 保留题与验证范围

六份模型源码固定到 KernelBench 提交 `423217d9fda91e0c2d67e4a43bf62f96f6d104f1`。原始代码和许可证在 `sources/KernelBench/`，任务模型、输入契约与文件哈希在 `tasks/`。所有 Model 类的语法树与原始源码一致；输入尺寸适配写在文件末尾，原类和输入工厂函数保持原样。

## 四道保留题

| 任务 | 正式名义输入 | 适配情况 |
| --- | --- | --- |
| Sigmoid | 16 × 393,216 | 仅减小原始批量，保留原始维度 |
| Softmax | 128 × 393,216 | 仅减小原始批量，保留超宽归约；另测 393,217 列的边界形状 |
| 带参数 LayerNorm | 16 × 64 × 256 × 256 | 原始名义尺寸和 affine 参数均保留 |
| GEMM、乘法、LeakyReLU 融合 | 1,024 × 8,192，输出宽 8,192 | 原始名义尺寸和参数保留 |

每题另有两组输入或构造参数。四题共 12 组配置已完成 eager 与 torch.compile 的实际 GPU 比较和非默认 stream 检查。LayerNorm 的基线峰值显存约 2.18 GB，超宽 Softmax 约 1.61 GB，本机 8 GB 显存可运行。结果索引为 `evidence/current-reference-baselines.json`。

最初准备的 Softmax 使用 4,096 列，虽然原公式未变，却降低了归约难度；已在正式实验前改回原始宽度。旧数据保留在 `evidence/reference-baselines/`，其中对应的 Sigmoid/Softmax 配置已被 `reference-baselines-wide/` 取代，不能当作当前保留题结果。

## 开发题

开发只使用 CUDA Agent 的 AXPBY，以及 KernelBench 的 RMSNorm 和 Cumsum。它们的模型调用、失败反馈可以进入规则维护；四道保留题的模型输出和反馈不能进入补写过程。当前只对保留题运行参考实现与编译基线，没有生成其候选解答。

## 独立正确性

验证使用工作区外的原始 Model，检查随机参数的 state_dict 兼容、数值结果、输入是否被修改、后续调用是否破坏先前输出，以及非默认 stream。Python/C++ 中经 PyTorch dispatcher 执行的张量计算会被检出，正常分配与属性访问保留；这与源码审阅和真实 kernel 启动记录共同使用。

超宽 Softmax 的单个概率很小，原始逐元素 `atol=1e-2` 会接受全零甚至错误的稀疏分布。因此还检查每行概率和接近 1，以及每行与参考的 L1 距离不超过 1e-3。这些检查已写入所有条件共同看到的任务契约。真正的 compiled Softmax 在三组配置上均通过了补充检查；两个能钻原容差空子的反例均被拒绝。

## 执行机制的实测

使用真实 CUDA 示例和合法 cuBLAS GEMM 进行了整条流程验证：受保护文件写入被拒绝；未编译、未验证、未计时的提交被拒绝；合法源码可编译并通过六项独立验证后提交；最后再修改 Python 文件，会使旧验证和计时失效，但不会无故要求重新编译未改动的原生源码。cuBLAS 的 3 × 7 与 7 × 5 矩阵乘法实际执行并与参考一致。

上述结果证明实验执行与测量条件可用。各文档条件是否改善保留题表现，要由随后封存的同版运行器对照数据回答。
