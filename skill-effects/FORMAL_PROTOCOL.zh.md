## 条件、任务与资源

按 DESIGN.zh.md 的十一组条件，四道保留题各运行两次，共 88 个预定运行。core、workflow、optimized 分别提供 9、23、45 个来源映射条目，原始九个代码或工作区示例保持共同。formatted 只改代码块外空白，optimized 合并重复措辞，length_control 将优化版补到原文 token 长度。原文和优化版分别有仅权限、权限加检查器对照；残余版只删去 C05—C07 显式提醒，保留示例。

随机种子为 20261019，先打乱任务/重复编号分块，再在每块内打乱条件。全部正式运行串行；不安装新库，不改变四题的公式、困难维度、评测输入和数值契约。使用 API 别名 deepseek-flash，高推理模式、temperature=1，每次最多 64 请求、96,000 生成 token（含推理），单次最多 32,768。工具子进程最多 180 秒。输入 token 实际记录，无单独强制输入总量上限。服务端 model、用量和可取得的指纹逐次保存，不声称别名能锁定未公开的服务端修订。

每次独立工作目录，从空候选开始。所供文档、共同任务与说明契约、运行器、参考模型、编译与验证工具按哈希固定。每轮启动前重查；变化即停止，不在同一协议中悄悄换版本。无任意 shell 工具。写入权限是接口权限，原生代码执行不被称作操作系统沙箱。

## 四个问题对应的比较

1. 原文规则的收益：core、workflow、optimized。分别报告共同条目和新增条目，不把子集间的内容变化冒充纯数量效应。
2. 处理收益与成本：original 对 formatted、optimized；optimized 对 length_control，观察重排、缩短和背景负荷。平台背景不是语义空白，相关比较限定于这组处理。
3. 遗漏与非量化部分：按共同尺度核对预期说明、测量解释、完整连贯的叙述、证据对应和失败陈述。不同条件未明确要求的原文事项仅作质量观察，不倒算违令。
4. 执行机制：同一原文或优化版下，比较无机制、仅权限、权限加检查器；再将 optimized_permissions_checker 与 residual_permissions_checker 配对，测量移除已覆盖提醒后的表现与成本。

## 结果及分母

先分开报告提交状态、独立编译、正确性、源码/文件约束、实际 kernel 活动、性能和说明质量，不给它们任意加权。完整目标达成需已提交、独立验证通过且候选/compiled 延迟不大于 0.95；是否满足全部适用要求另列，不能仅靠数值通过宣告。

正确性使用独立参考、不同种子、固定参数、边界形状、重复调用与非默认 stream，并核对输入及旧输出。Softmax 补充分布检查。计时采用预热后的七组配对 CUDA event 样本，保存 eager、compiled、candidate 原始样本和中位数；它测量完整调用与 launch 间隔，不是纯 kernel 时间。Nsight 的实际 kernel 活动核查另存；不可执行的失败实现不因缺少 trace 而被删掉。

所有预定运行进入 88 次总交付分母。步数/生成预算用尽、截断、未提交、API/轨迹错误和基础设施不完整分别列出。不按效果重跑，不以成功样本替代失败。基础设施中断先保留该槽位和已产生用量，再检查实际子进程终态；只继续尚未执行的槽位。测量故障的敏感性分析可以另报，不能替代全部运行的结果。

未提交的运行仍独立评测最后文件，但“代码正确”和“成功交付”分列。没有最终说明的运行计说明缺失；只在有说明子集上的文风分数必须同时给出各条件说明可取得率，防止遗漏未交付样本。
