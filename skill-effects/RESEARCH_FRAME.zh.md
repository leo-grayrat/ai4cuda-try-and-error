# 研究起点与证据安排

## 起点（用户于 2026-10-19 明确）

AI 遇到问题便追加一条禁令或要求，积成几千行的说明文档。这种逐次打补丁的做法很差劲，也容易让后续模型忽略其中的要求。研究先检验这条累积路径，再考察压缩，以及把要求交给权限和检查器执行。

## 采用的 Nature 工作流

本机没有名为 `nature-paper` 的独立技能。采用已安装的 `nature-writing` 及其研究论文、实验章节流程；配图和独立审阅分别在对应阶段使用 `nature-figure` 与 `nature-reviewer`。当前处于问题与证据规划阶段，结果完成后先写结果，再组织引言和讨论，摘要最后写。研究类型为实证研究；当前工作语言为中文，目标期刊未指定。

一句话研究问题：在真实 CUDA 开发任务中，失败驱动的追加规则如何改变任务表现、遗漏和成本，同一批要求经压缩或交给工具执行后会有什么变化？

## 术语

| 名称 | 本研究中的意思 |
| --- | --- |
| 累积文档 | 遇到开发问题后逐次追加要求形成的文档，保留追加历史 |
| 独立要求 | 去掉同义重复之后的一项要求 |
| 重复告诫 | 对已有要求的再次强调或改写 |
| 压缩版 | 保持适用要求和含义，减少重复和文字的文档 |
| 执行机制 | 工具实际拒绝越权操作，或检查器检出违例并要求修正 |
| 遗漏 | 适用且明确提出的要求在轨迹或交付中没有落实 |

## 主张与所需证据

| 待检验问题 | 所需直接证据 | 当前状态 |
| --- | --- | --- |
| 追加规则改善任务吗 | 累积各阶段在相同保留任务上的正确性、性能与违例 | 待实验 |
| 收益抵得上成本吗 | 同批运行的输入、输出、缓存、工具和交付质量 | 待实验 |
| 是否遗漏部分或非量化要求 | 共同要求逐项复核、隐藏条件的说明质量审阅、原文例子 | 待实验 |
| 压缩有帮助吗 | 同一要求集合追加原文与压缩版的比较 | 待实验 |
| 权限和检查器更有效吗 | 相同文档和预算下的机制对照，包括返工和误拒绝 | 待实验 |

几千行文档的来源及形成过程是研究材料的一部分。不能只有短版和原版两份最终文件，缺少累积过程；也不能先假定追加必然失败，再选择支持这个结论的样本。
