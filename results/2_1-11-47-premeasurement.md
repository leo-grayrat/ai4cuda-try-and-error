## 预先划出的动作与对照

1. **就地写回卷积输出。**父版本为 Triton 后处理创建新输出张量，子版本默认让 `out=x`，kernel 在读取后把每个位置写回原张量。预期省去分配和一份输出存储管理，可能改善整条运行时间。单独撤销版仅让默认路径重新分配 `torch.empty_like(x)`，保留子版本的 kernel 与启动方式；若正确，比较它与子版本的延迟。
2. **二维改三维启动网格。**父版本以 `(N*C, 空间块)` 启动，kernel 内做 `idx_nc % C`；子版本以 `(N,C,空间块)` 启动，直接读取通道编号。这个决策跨 kernel 索引和 host 启动两处代码，必须一起撤销。预计可能减少取模，但网格变化也可能带来代价，事前不指定速度方向。
3. **把三种自动调优配置缩成一个。**子版本只留 `BLOCK=1024, num_warps=8`；父版本另有 256、512 配置。单独撤销版恢复三种配置，其余保持子版本。实际选中配置与速度取决于本机任务形状，事前不指定方向。计时需注意自动调优的缓存和预热，不能把首次编译时间当 kernel 延迟。
4. **普通可执行对照：bias 连续性整理。**父版本无条件调用 `bias.view(-1).contiguous()`，子版本先检查连续性再按需调用。对该题常见的连续 bias，预计两者得到同一视图，不产生可解释的 GPU 性能变化。对照版仅恢复父版本这段 host 代码；如果实际正确性或速度出现变化，如实记录，不强说它“普通”。

前 3 项各建一个“子版本减去该动作”的候选；第 4 项是对照。候选代码先做静态审阅，再做正确性。若任何单独撤销与其他动作存在未预见的依赖，使程序错误，则将其标为无法比较性能，并记录依赖关系。比较使用同一参考、GPU 和至少三轮乱序计时；效应只表示在当前子版本上下文中的条件差别。
