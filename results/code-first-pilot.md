# 代码优先信用分配：首轮真实轨迹筛查

## 本轮要回答什么

从真实父子源码中先圈出可能改变运行时间的代码动作，跳过未变代码与说明文字，再用“在子版本中撤销动作”的正确性和速度核查定位。这里不把父子整段速度差自动分给每个改动，也不从公开档案推断生成 token。

## 数据与评测

- 来源：AdaExplore Level 2 档案中有明确父节点、档案内父子均标记正确且源码不同的修改。首选的九条覆盖逐元素/尾处理、归约和矩阵相关题目，另补三条候选；每条先在本机重新核对父子。
- 本机：NVIDIA GeForce RTX 5060 Laptop GPU，设备 UUID `GPU-1265274a-9013-e311-19fa-35659d490047`；KernelBench 修订 `423217d9fda91e0c2d67e4a43bf62f96f6d104f1`，每候选 5 次正确性试验和 30 次计时试验。重复轮次用不同 `--order-seed` 打乱候选顺序。原始记录在未入库的 `runs/` 中。

## 已测到的内容

- `2_9`：子版本在 `linear` 处启用 FP16 autocast、使用原地 ReLU，再转回 FP32。五轮父/子都通过本机参考；父/子速度比的中位数为 **3.123**。该改动混合了精度和尾处理，不能作为“找到算法核心”的代表；撤销整个修改只重得父版本。
- `2_55`：子版本引入新的部分和暂存、预计算的成对权重与矩阵路径、相应的输入输出连接。初版分组把说明文字误纳入动作。修正后 kernel 文档字符串不再凭关键词获得高分；只撤销高分计算行的候选不能正确运行，说明低分的数据连接代码也属于共同动作。把共享新变量的连接语句并回动作、把文档留在外面后，四种候选连续三轮均通过正确性。父/子速度比中位数 **1.6754**；撤销共同动作相对子版本的对数延迟差中位数 **0.5162**，撤销一处文档说明对照为 **-0.00007**。修正版仍是一组跨 14 个差异块的变换，不能分别认领每行的贡献。每轮比只测父子多评测两个候选。
- 同一修改的初版分组还做了五轮随机顺序测量：父/子速度比中位数 **1.676**，撤销大动作的对数延迟差中位数 **0.5167**，撤销说明文字对照为 **0.00008**。初版动作混入文档差异，因此这些数只用作定位器修正前的核查记录。
- `2_56`：父版本执行 `w.t().contiguous()` 并单独矩阵乘、加偏置；子版本改为 `torch.nn.functional.linear(x,w,b)`，避免显式物化大转置。三轮父子都通过本机参考；父/子速度比为 `10.336`、`10.370`、`10.366`，中位数 **10.366**。这里整段修改只有一个差异块，撤销后就是父版本；它验证了一个明确的框架调用与数据搬运优化，不能检验定位器是否比差异基线找得更准，也没有可用的普通代码对照。

## 当前结论与下一道门槛

这轮证实了可以从真实父子源码生成可检查的动作候选、普通代码对照和完整证据链，也暴露了“代码结构定位”自身的误报与依赖问题。**尚未证明**定位器优于按文本差异或差异分块阅读：只有一条多处协同的结构动作同时具备正确性、独立的普通代码对照和重复计时，另一条正确的框架调用优化只有一个差异块。没有九条可用的算法修改，也没有按任务划分的留出集。因此不扩展为 30 条训练数据，不启动本机学习实验。

后续先补到三类题目各三条本机正确的真实修改，人工标注关键动作与普通代码，在相同阅读预算下比较召回、误报和额外 GPU 测量次数；有稳定留出优势后才采集带原始回复与真实 token 偏移的新短轨迹。公开 AdaExplore 档案没有生成 token，`trace.json` 中相应字段保持 `null`。当前只有一块 GPU，跨设备实验暂停。
