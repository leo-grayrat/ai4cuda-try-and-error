# 论文创作过程记录

本文件记录 `paper.md` 的完整创作过程，包括过程中的错误与修正。它不是论文的一部分，而是本次 human-AI 协作的留痕。

## 一、研究起点（用户既有判断）

本研究检验的命题来自用户 2026-09-13 撰写的调研稿（`D:\File\Markdown\近日对 AI4CUDA 的调研.md`）。该稿对 CUDA Agent 的因果链提出四条反驳：

1. CUDA 代码中绝大多数 token 不专属 CUDA，真正专属的只有 `threadIdx.x`、`__shared__`、`__syncthreads()` 等少数标识符，而它们"恰恰非常固定、非常模式化"；
2. 生成时的关键量是当前上下文下的条件概率，与预训练语料 0.01% 的绝对占比无关；
3. 论文自身数据显示基础模型并非"不会写 CUDA"（Seed1.6 正确率 74%，Level 1 达 90%）；
4. 若真有低概率，更可能来自长工具 Agent 吞入的分布外上下文。

**论文的 RQ1 检验第 1、2 条，RQ2 检验第 4 条。**

## 二、路线演化

**第一轮（本地 vLLM + Qwen3-4B-AWQ）**。起因是闭源 API 不返回工具调用参数的 logprob。该轮打通了链路（NO_PROXY、skill 禁用、关闭 thinking、对齐基准等），采得 15987 个 token。

**该轮的细分结论已全部撤回**，见第四节。

**第二轮（plain chat + deepseek-chat）**。放弃 agent 框架：不提供 tools，要求模型把 kernel 写在回复正文，由驱动负责写文件、执行评测、构造反馈。最小验证测得代码块内 **448/448** 个 token 均带 logprob，路线成立。正式采集 128 次（4 任务 × 2 条件 × 16 重复），127 次有效，98,533 个 token。

## 三、关键决策及其依据

| 决策 | 依据 |
|---|---|
| 放弃 agent 框架 | 工具调用参数不受 `logprobs` 覆盖；实测 448/448 正文 token 有 logprob |
| 选 `deepseek-chat` 而非 `deepseek-flash` | 实测：推理模型在 `max_tokens=4000` 时预算被思考耗尽、content 返回空 |
| 双反馈条件（完整/截断） | PLAN 原定的干预对照，用于分离"反馈信息量"与"失败事件本身" |
| 两种 token 定义边界 | 第一轮的失败教训，见下节 |

## 四、过程中的重大错误（如实记录）

**分类偏差导致假显著。** 第一轮分析中，`classify.py` 在散文段**刻意排除**了 `load`/`zeros`/`store`（理由：这些词在英文散文里也出现，怕误判）。后果是同一个词按所在段被切进不同类别：

```
load 判为 NL_reasoning      n=6   mean=-0.044  lowprob= 0.00%
load 判为 triton_specific   n=4   mean=-1.034  lowprob=25.00%
```

`triton_specific` 因此只捕获 20 个 token（全量 451 个），而这 20 个恰好含两个极端采样值，产出 **`p=0.0156`、低概率率 10%** 的假显著结论。该结论被连续数轮当作发现向上叠加（分位数、工具维度、位置效应、"API 选择点"机制），全部作废。

**发现方式**：在用户要求"展开分析"后，改用全量匹配（不依赖分段）重算，p 立即变为 0.211。

**教训已固化**：正式结果同时报告两种定义边界（宽松表 p=0.0070、严格表 p=0.0007），方向必须一致才下结论。

## 五、其他影响实验的工程问题

- **`NO_PROXY` 未设置**：系统代理拦截回环请求，返回 502，使 opencode 侧表现为"服务器错误"。
- **OpenCode 的 skill 加载**：53 个 skill 撑爆 8192 上下文窗口，触发无限压缩循环。解法是自定义 agent `tools: {skill: false}`。
- **推理模型的 thinking**：4B 与 `deepseek-flash` 都会把输出预算烧在思考上而不产出内容。
- **`subprocess` 未关 stdin**：探测进程在管道链中挂起 40 分钟。
- **WSL 环境误装**：第一轮的环境装进了 C 盘发行版（32 GB），后发现并迁移至 D 盘。
