# 论文创作过程记录（v2）

本文件记录 `stage2_write/paper.md` 的完整创作过程，包括 v1 → v2 的演进、两次方法学失误、以及用户介入如何改变实验设计。

## 一、起点与 v1

最初的问题是检验 CUDA Agent 的因果链：CUDA 在预训练语料中 <0.01% → 语法稀有 → token 条件概率近 10⁻⁹ → 精度差异放大 → 训练崩溃。

v1 只测了第二环，用四道元素级/归约任务（128 次运行，98,533 token）。结论是"CUDA 词汇不构成低概率尾部"（0.26% vs 0.84%，p=0.0007）。

## 二、v1 的三处不足，以及它们怎么被发现

**不足一：任务太简单。** 四道题全是行求和、逐元素、行归一化、行 softmax。这是用户直接指出的：「你为什么到现在才能发现？你忘了你批评自己只取了一道简单题时候的样子了吗？」

事实是：KernelBench Level 2 的 100 道题一直躺在 `.cache/KernelBench/level2` 里，项目跑了一个多月，从未打开过。**不是数据不存在，是没有去看。**

**不足二：观测量被二值化。** v1 只报"logprob ≤ −2 的比例"。这个数丢失了分布信息，而且**无法与 10⁻⁹ 直接比较**——比例是一个率，10⁻⁹ 是一个概率。v2 改为报分位数、极小值、概率质量分配，并把 `exp(min logprob)` 算出来直接对照。

**不足三：分类靠关键词表。** v1 的分类器在散文段排除 `load`/`zeros`/`store`，导致 `triton_specific` 只捕获 20/451 个 token，产出假显著 p=0.0156。这个错误在 v1 中已撤回并记录，但**撤回了数字，没换方法**——v2 才改成逐条读原文。

## 三、手工阅读的两次

**第一次：816 个（Family A）。** 导出到 `results/lowprob-contexts.txt`，逐条读前后各 45 字符。结果：注释约 75%、标识符约 12%、标点约 10%、对话散文约 4%、控制流约 1%。

**第二次：189 个（Family B 非注释代码内，logprob ≤ −4.5）。** 导出到 `results/kb2-code-noncomment-extremes.txt`，逐条读。结果：标识符约 110、标点约 40、注释漏检约 15、数字约 8、方法调用约 8、操作符约 6、**语法写法约 5**。

**两次都没有出现"实现选择"位置的低概率。** 最极端的几个是 `' //'`（`BLOCK // 1`，−13.02）、`'|='`（想写 `=`，−16.65）、`' bi'`（`biasp_ptr`，−8.85）——都是笔误或占位符。

## 四、评审如何改变了论文

五位评审提出八项要求，其中两项是**重新计算**而非改文字：

**要求二：排除代码块内注释后重算 code rate。** 结果从 0.60% 降到 **0.33%**，五个任务全部下降，**与 prose 的对比从 22.4 倍升到 41 倍**。魔鬼代言人当时预测"论文在通过报告混合值低估自己的发现"，事实证明如此。

**要求三：把跨家族比较换成家族内比较。** 原比较有四个混杂（任务构造、轮数上限、成功率、上下文构成）。换成 Family B 内部五个任务的比较后，成功率从 0/8 到 5/8，code rate 只在 0.18%–0.44% 之间波动，**不以成功率为转移**。这个不变性主张比原来干净得多，而且用的全是已有数据。

**要求一改变的是主张本身**：从"第二环不成立"改为"**无论 10⁻⁹ 测的是什么，它都不是领域词表的属性**"。理由是：对齐不能改变语料统计，所以若低概率来自语料稀有，它应当在对齐后依然存在。实测是 1.0。

## 五、v2 数据采集中的两个失误

**失误一：驱动把片段当完整文件。** 39 个 run 里有 14 个（36%）最后一轮输出的是代码片段（63–239 字符），驱动无条件接受，导致 `NameError`。剔除之后，完整文件 run 的成功率是 28%（7/25），而不是总体 17.5%。

**失误二：显存估算漏算峰值。** `19_convtranspose2d_gelu_groupnorm` 四个 run 全部 OOM——建任务时只算了输入大小，没算"参考实现 + 候选 + 中间结果"同时在显存里的峰值。

这两项使 Family B 的成功率只有 17.5%、`after_failure` 占 87.5% token。这个偏差已在摘要、§4.2、§6.4 三处标注。

## 六、用户介入

- 指出 v1 只测了简单题，且 KernelBench 就在本地没看（直接改变了 v2 的实验设计）
- 指出"变量名和注释不影响代码正确性"，要求区分"影响任务的选择"与"措辞自由"（改变了 §4.7 的分类框架）
- 要求手工读原文而非依赖关键词表（改变了分类方法）
- 要求不要用"模型不同"作为削弱结论的挡箭牌（改变了 §5.1 的论证方式）
- 要求分次提交（改变了工作流程）
