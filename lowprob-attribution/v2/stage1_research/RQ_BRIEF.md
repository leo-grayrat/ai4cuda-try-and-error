# Stage 1 — RQ Brief (v2)

体裁：Empirical critique + replication. 模式：full（但保留阶段结构，不做无谓的多轮推敲）。

---

## 1. 命题

CUDA Agent 把 PPO 训练在第 17 步的崩溃归因于一条四环因果链，其中第二环是一个**可测量的经验断言**：

> 因为 CUDA 代码占预训练语料不足 0.01%，策略对 CUDA token 必须赋近数值下限的概率，例如 **πθ(aₜ|sₜ) ≈ 10⁻⁹**。

v2 检验的是：**这个断言在什么条件下成立？如果成立的范围极窄，那条因果链的归因是否还站得住？**

## 2. 四环，以及本文的边界

| 环 | 内容 | v2 的状态 |
|---|---|---|
| (i) 语料占比 | CUDA < 0.01% 预训练数据 | **不检验**（需语料统计，不可公开核验） |
| (ii) 生成时概率 | 该占比导致 CUDA token 条件概率近 10⁻⁹ | **本文核心检验** |
| (iii) 精度放大 | 近下限概率使 BF16/FP16 差异放大为比率方差 | 不检验（需双引擎训练） |
| (iv) 训练崩溃 | 比率爆炸导致 17 步崩溃 | 不检验（需训练） |

(ii) 是 (iii)(iv) 的前提。**若 (ii) 在可观测的全部条件下都不成立，(iii)(iv) 的归因失去依据。**

## 3. v2 相对 v1 的三个实质推进

**推进一：任务难度从"归约"升到"融合"。** v1 只用 4 道元素级/归约题（代码块内密度 0.67%）。v2 增加 KernelBench Level 2 的 5 道多算子链（ConvTranspose3d + GroupNorm + GELU + Sum 这类），算子链长 3–6 倍，需要决定融合边界、中间结果物化、tile 切分。**结论：代码块内密度 0.60%，没有上升。**

**推进二：从"低概率率"换成"概率分布"。** v1 只报 logprob ≤ −2 的比例（二值化），丢失分布信息。v2 报分位数、极小值、概率质量分配，并把实测的绝对概率与论文的 10⁻⁹ 直接对齐：

```
code  p1 = −1.36   min = −13.02  (2.2×10⁻⁶)
prose p1 = −5.84   min = −16.65  (5.9×10⁻⁸)
论文声称 10⁻⁹  ⇔  logprob = −20.7
```

**推进三：从关键词表换成逐条读原文。** v1 的分类器在散文段排除了 `load`/`zeros`/`store`，导致 `triton_specific` 只捕获 20/451 个 token，产出假显著 p=0.0156（后已撤回）。v2 改为**手工逐条读**：816 个（简单题）+ 189 个（Level 2 非注释高代价 token）全部人工归类，不预设词表。

## 4. 判读树（采集前冻结）

- **判读 1**：代码块内低概率率**不高于** prose，且**不随难度上升** → 因果链第二环不成立
- **判读 2**：代码块内低概率率**显著高于** prose，或**随难度上升** → 第二环可能成立，需进一步分层
- **判读 3**：混合 → 需按 token 类型细分

**v2 的实测落点：判读 1。** 代码块内 0.60% vs prose 13.56%（22.4 倍差距，方向与假设相反）；简单题 0.67% → Level 2 0.60%，**难度增加未改变代码块内密度**。

## 5. 差异点

| 最近邻 | 做法 | v2 的差别 |
|---|---|---|
| CUDA Agent | 训练侧归因，未公开逐 token 概率 | v2 直接测生成时条件概率，且给出分布而非单一量级 |
| DR. KERNEL | MRS + token 否决稳定训练，不提升上限 | v2 从推理侧给出独立证据：不确定性随体裁变化，不随领域词汇变化 |
| 精度不匹配系列 | 假定概率已在下限 | v2 检验该假定，发现实测最低 −13.0，比 10⁻⁹ 高 400 倍 |

## 6. 可证伪性

**若在未微调的基模上测出 CUDA token 概率接近 10⁻⁹**，则 v2 的结论（"在已对齐模型上不成立"）与原文可同时成立。v2 未做该对照（需基模权重），并在正文明确标注。

**v2 的结论若被推翻，最可能的方式是**：在结构级指标上发现"实现选择"位置的不确定性远高于 token 级的观测。这一点 v2 未测，是它公开的边界。

## 7. 不能回答

- 低概率是否真的导致 PPO 比率爆炸（需训练）
- train-inference mismatch 的贡献比重（需双引擎）
- 结构级决策的困难（需新指标，见 §6）
